# 記憶體 (Memory) 隨機也比順序存取慢，帶你深入理解記憶體 IO 過程

> 原文標題：内存随机也比顺序访问慢，带你深入理解内存IO过程

> 原文連結：https://mp.weixin.qq.com/s/ps8VfGpbL4-xKggM2ywjHw

---

平時大家都知道記憶體存取很快，今天來讓我們來把刨根問底的精神發揮到極致，來思考兩個問題

問題 1：記憶體存取延遲到底是多少？你是否會進行大概的估算？
例如筆者的記憶體條的  Speed 顯示是 1066 MHz，那是否可以推算出記憶體 IO 延遲是  `1s/1066` MHz=0.93ns?
這種演算法大錯特錯。

問題 2：記憶體存在隨機 IO 比順序 IO 慢的問題嗎？
我們都知道磁碟 (Disk) 的隨機 IO 要比順序 IO 慢的多（作業系統 (Operating System) 底層還專門實作了電梯排程演算法來緩解這個問題），那麼記憶體的隨機 IO 會比順序 IO 慢嗎？

要想徹底弄明白以上兩個問題，我想我們得從記憶體 IO 的實體過程中來尋找答案。

## 先給你講個圖書管理員的故事

在開始介紹枯燥的記憶體工作原理之前。我想先給你講一個故事，並帶你去認識一個人，圖書館的管理員。

在我們的這個故事中，你是故事的主角。你有一所房子，房子裡有一個僕人，他每天幫你處理各種各樣的圖書資料。但是北京房價太貴，所以你的這個房子很小，只能放的下 64 本書。你家的馬路對面，就是北京圖書館 (你家房子雖然小但是地段還不錯)，你所需要的所有的圖書在那裡都可以找到。圖書館有個管理員，他負責幫你把你想要的書找出來。

好接下來，導演喊了 action，場景開始！

- 場景 1：
你發現你需要編號為 0 的書的計算結果，你的僕人穿過馬路告訴了圖書管理員，告訴他請幫我把第 0-63 本書取出來。圖書管理員幫你在電腦前查得該書在二樓。 於是他，花了點時間坐電梯到了二樓。等到了二樓，他又花了點時間幫你找了出來。然後你的僕人抱著 64 本書放到了客廳，拿起第 0 本書幫你處理了起來。

- 場景 2：
你發現你需要編號為 1 的書的計算結果，告訴你的僕人。你的僕人直接從客廳拿出來就可以處理了，這次你等的時間最短。

- 場景 3：
你發現需要編號為 65 的書，你又告訴你的僕人。你的僕人穿過馬路又去找了圖書管理員。圖書管理員還在二樓呢，聽說這次需要 65-127，這次他不用再花時間找樓層了。只是花時間找書就可以了。你的僕人把 65-127 的書放到了客廳（以前的 0-63 就都扔了），並幫你開始處理起 65 號書來。

- 場景 4：
你發現你需要編號為 10000 的書，你告訴了你的僕人。你的僕人穿過馬路去圖書館，找到了管理員。這次管理員查得你需要的書是在 10 樓，他得花點時間坐電梯過去。去了之後，他又得花點時間幫你找出來。

這四個場景裡，我覺得你一定發現了不同情形下耗時的差異。

- 場景 1 和場景 4 花費的時間最多。因為圖書管理員需要花時間坐電梯找樓層，需要花時間在樓內找書。
- 場景 3 次之，因為圖書管理員直接就在樓層內，只需要花時間在樓內找書既可
- 場景 2 最快，因為只需要僕人幫你從客廳拿過來就好，連馬路都不需要過。

之所以編造這麼一個例子，是因為記憶體的工作方式和它太像了。 接下來我們進入記憶體的實際分析。

## 記憶體的實體結構

在《帶你理解記憶體對齊 (Memory Alignment) 最底層原理！》中我們瞭解了記憶體顆粒的實體構造以及 IO 過程，今天我們再來複習一下。

記憶體是由 chip 構成。每個 chip 內部，是由 8 個 bank 組成的。其構造如下圖：

而每一個 bank 是一個二維平面上的矩陣，前面文章中我們說到過。矩陣中每一個元素中都是儲存了 1 個位元組，也就是 8 個 bit。

每當 CPU 向記憶體請求資料的時候，記憶體晶片總是 8 個 bank 並行一起工作。每個 bank 在定位到行位址後，把對應的行 copy 到 row buffer。 再根據列位址把對應的元素中的資料取出來，8 個 bank 把資料拼接一下，一個 64 位寬的資料就可以回傳給 CPU 了。

## 記憶體 IO 延遲

在《從 DDR 發展到 DDR4，記憶體核心頻率指標其實基本上就沒太大的進步。》裡的結尾處，你應該記得我們提到了記憶體有  CL-tRCD-tRP-tRAS 四個參數。 我們今天來詳細理解一下這四個參數的含義：

- CL(Column Address Latency）：傳送一個列位址到記憶體與資料開始響應之間的週期數
- tRCD（Row Address to Column Address Delay）：開啟一行記憶體並存取其中的列所需的最小時鐘週期數
- tRP(Row Precharge Time)：發出預充電命令與開啟下一行之間所需的最小時鐘週期數。
- tRAS(Row Active Time)：行活動命令與發出預充電命令之間所需的最小時鐘週期數。也就是對下一次預充電時間進行限制。

要注意除了 CL 是固定週期數以外，其他的三個都是最小週期。另外上面的參數都是以時鐘週期為單位的。因為現代的記憶體都是一個時鐘週期上下沿分別各傳輸一次資料，所以用  `Speed/2` 就可以得出，例如筆者的機器的 Speed 是 1066 MHz，則時鐘週期為 533 MHz。你自己的機器可以透過 `dmidecode` 命令檢視：

```
# dmidecode | grep -P -A16 "Memory Device"
Memory Device
        ......
        Speed: 1067 MHz
        ......
```

和「圖書管理員」類似，記憶體晶片也有類似的工作場景：

- 場景 1：
你的程序 (Process) 需要記憶體位址 0x0000 為的一個位元組的資料，CPU 這時候向記憶體控制器 (Memory Controller) 發出請求，記憶體控制器進行行位址的預充電，需要等待 tRP 個時鐘週期。再發出開啟一行記憶體的命令，又需要等待 tRCD 個時鐘週期。接著傳送列位址，再等待 CL 個週期。最終將 0x0000-0x0007 的資料全部回傳給了 CPU。 CPU 把這些資料放入到了自己的 cache 裡，並幫你開始對 0x0000 的資料進行運算。

- 場景 2：
你的程序需要記憶體位址 0x0003 的一個位元組資料，CPU 發現發現它在自己的 cache 裡存在，直接使用就好了。這個場景裡其實根本就沒有記憶體 IO 發生。

- 場景 3：
你的程序需要記憶體位址 0x0008 的一個位元組資料，CPU 的 cache 並沒有命中，於是向記憶體控制器請求。記憶體控制器發現行位址和上一次工作的行位址一致，這次只需要傳送列位址後等待 CL 個週期，就可以拿到 0x0008-0x0015 的資料並回傳給 CPU 了。

- 場景 4：
你的程序需要記憶體位址 0xf000 的一個位元組資料，同樣 CPU 的 cache 並不命中，向記憶體控制器請求。記憶體控制器一看（內心有些許的鬱悶），這次行位址又變了，得，和場景 1 一樣。繼續等待 tRP+tRCD+CL 個週期後，才能夠取到資料並回傳。

> 實際的電腦的記憶體 IO 過程中還需要進行邏輯位址和實體位址的轉換，這裡忽略不表。

## 結論

其中場景 1 和場景 4 是隨機 IO 的情況，場景 2 無記憶體 IO 發生，場景 3 是順序 IO，。透過上面的過程描述我們可以得到結論。記憶體也存在和磁碟一樣，隨機 IO 比順序 IO 要慢的問題。如果行位址同上一次存取的不一致，則需要重新複製 row buffer，延遲週期需要 tRP+tRCD+CL。而如果是順序 IO 的話（行位址不變），只需要 CL 個週期既可完成。

我們接著估算下記憶體的延遲，筆者的機器上的記憶體參數  Speed 為 1066 MHz（透過  `dmidecode` 查得），該值除以 2 就是時鐘週期的頻率=`1066/2`=533 MHz。其延遲週期為 7-7-7-24。

- 隨機 IO
這種狀況下需要 tRP+tRCD+CL 個時鐘週期，7+7+7=21 個週期。但是還有個 tRAS 的限制，兩次行位址預充電不得小於 24。所以我們得按 24 來計算，24*(`1s/533` MHz) = 45ns

- 順序 IO
這種狀況下只需要 CL 個時鐘週期 7*(`1s/533` MHz)=13ns

## 擴充套件：回顧 CPU 的 Cache Line

因為對於記憶體來說，隨機 IO 一次開銷比順序 IO 高好幾倍。所以作業系統在工作的時候，會盡量讓記憶體透過順序 IO 的方式來進行。做法關鍵就是 Cache Line。當 CPU 發現快取 (Cache) 不命中的時候，實際上從來不會向記憶體去請求 1 個位元組，8 個位元組這種。而是一次性就要 64 位元組，然後放到自己的 Cache 中存起來。

用上面的例子來看，

- 如果隨機請求 8 位元組：耗時是 45ns
- 如果隨機請求 64 位元組：耗時是 45+7*13 = 136ns

開銷也沒貴多少，因為只有第一個位元組是隨機 IO，後面的 7 個位元組都是順序 IO。資料是 8 倍，但是 IO 耗時只有 3 倍，而且取出來的資料後面大機率要用，所以電腦內部就這樣做了，透過這種方式幫你避免一些隨機 IO！

另外，記憶體也支援 burst(突發傳輸) 模式，在這種模式下可以只傳入一次行列位址，就命令記憶體回傳該記憶體開頭的連續位元組資料，例如 64 位元組。這種模式下，只有第一次的 8 位元組需要真正的行列存取延遲，後面的 7 個位元組可以直接按記憶體的資料頻率給吐出來，耗時更短。
