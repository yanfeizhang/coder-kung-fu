# NUMA 架構下的記憶體 (Memory) 存取延遲區別！

大家好，我是飛哥！
現在的伺服器實體主機 CPU 一般都是多個 CPU，核數也是十幾甚至幾十核。記憶體幾十 GB 甚至是上百 G，也是由許多的記憶體條組成的。那麼我這裡思考一下，這麼多的 CPU 和記憶體它們之間是怎麼互相連線的？同一個 CPU 核存取不同的記憶體條延遲一樣嗎？
在《記憶體隨機存取也比順序慢，帶你深入理解記憶體 IO 過程》中我們瞭解了記憶體存取時晶片內部的執行過程，在《實際測試記憶體在順序 IO 和隨機 IO 時的存取延遲差異》中我們又進行了實際的程式碼測試。不過這兩文中我們都把精力聚焦在記憶體內部機制，而回避了上面的問題，那就是 CPU 和記憶體的連線方式，也就是匯流排架構。

## 回顧 CPU 與記憶體的簡單連線：FSB 時代

我們先來回顧下在歷史上 CPU、記憶體數量比較少的年代裡的匯流排方案-FSB。FSB 的全稱是 Front Side Bus，因此也叫前端匯流排。CPU 透過 FSB 匯流排連線到北橋晶片，然後再連線到記憶體。記憶體控制器 (Memory Controller) 是整合在北橋裡的，Cpu 和記憶體之間的通訊全部都要透過這一條 FSB 匯流排來進行。

在這個年代裡，當時提高電腦系統整體效能的方式就是不斷地提高 CPU、FSB 匯流排、記憶體條的資料傳輸頻率。

## 如今多 CPU 多記憶體條複雜互聯：NUMA 時代

當 CPU 的主頻提升到了 3GHz 每秒以後，硬體製造商們發現單個 CPU 的已經到了實體極限了。所以就改變了效能改進的方法，改成為向多核、甚至是多 CPU 的方向來發展。在這種情況下，如果仍然採用 FSB 匯流排，會導致所有的 CPU 和記憶體通訊都經過匯流排，這樣匯流排就成為了瓶頸，無法充分發揮多核的優勢與效能。所以 CPU 製造商們把記憶體控制器從北橋搬到了 CPU 內部，這樣 CPU 便可以直接和自己的記憶體進行通訊了。那麼，如果 CPU 想要存取不和自己直連的記憶體條怎麼辦呢？所以就誕生了新的匯流排型別，它就叫 QPI 匯流排。

圖中 CPU1 如果想要存取記憶體 3 的話，就需要經過 QPS 匯流排才可以。

## 動手檢視 Linux 下 NUMA 架構

我們先透過 `dmidecode` 命令檢視一下記憶體插槽，單條大小等資訊。大家可以試著在 linux 上執行以下該命令。輸出結果很長，大家可以有空仔細研究。我這裡不全部介紹，這裡只挑選一些和記憶體相關的：

```
# dmidecode|grep -P -A5 "Memory\s+Device"|grep Size

        Size: 8192 MB

        Size: 8192 MB
        Size: 8192 MB

        Size: 8192 MB
        Size: No Module Installed
        Size: 8192 MB
```

可以看出，我當前使用的機器上共有 16 個記憶體插槽，共插了 8 條 8G 的記憶體。所以總共是 64GB。如我們前面所述，在 NUMA 架構裡，每一個實體 CPU (Physical CPU) 都有不同的記憶體組，透過 `numactl` 命令可以檢視這個分組情況。

```
# numactl --hardware
available: 2 nodes (0-1)
node 0 cpus: 0 1 2 3 4 5 12 13 14 15 16 17
node 0 size: 32756 MB
node 0 free: 19642 MB
node 1 cpus: 6 7 8 9 10 11 18 19 20 21 22 23
node 1 size: 32768 MB
node 1 free: 18652 MB
node distances:
node   0   1
  0:  10  21
  1:  21  10
```

透過上述命令可以看到，每一組 CPU 核分配了 32GB（4 條）的記憶體。node distance 是一個二維矩陣，描述 node 存取所有記憶體條的延遲情況。node 0 裡的 CPU 存取 node 0 裡的記憶體相對距離是  10,因為這時存取的記憶體都是和該 CPU 直連的。而 node 0 如果想存取 node 1 節點下的記憶體的話，就需要走 QPI 匯流排了，這時該相對距離就變成了 21。

所以、在 NUMA 架構下，CPU 存取自己同一個 node 裡的記憶體要比其他記憶體要快！

## 動手測試 NUMA 架構記憶體延遲差異

`numactl` 命令有 --cpubind 和--membind 的選項，透過它們我們可以指定我們要用的 node 節點。還沿用《用程式碼讓你來實際感受記憶體的在不同情況下的存取延遲差異》裡的測試程式碼

1、讓記憶體和 CPU 處於同一個 node

```
# numactl --cpubind=0 --membind=0 ./main
Delay  (ns)

s1      1.28    1.28    1.26    1.25    1.26    1.26    1.28    1.43    1.43

s64     1.28    1.26    1.26    1.82    2.43    2.48    3.15    8.82    8.92
andom   2.40    2.40    2.40    2.40    4.80    4.80    19.20   28.80   52.80
```

## 結論

透過上面的各個小節我們可以看到，現代的伺服器裡，CPU 和記憶體條都有多個，它們之前目前主要採用的是複雜的 NUMA 架構進行互聯，NUMA 把伺服器裡的 CPU 和記憶體分組劃分成了不同的 node。從上述實驗結果來看，拿 8M 陣列，迴圈步長為 64 的 case 來說，同 node 耗時 3.15 納秒，跨 node 為 3.96 納秒。所以屬於同一個 node 裡的 CPU 和記憶體之間存取速度會比較快。而如果跨 node 的話，則需要經過 QPI 匯流排，總體來說，速度會略慢一些。
