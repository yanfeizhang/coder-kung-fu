如何正確獲取容器的CPU利用率？

大家好，我是飛哥！

今天我們來深入理解關於容器 cpu 利用率相關的兩個問題。

第一個問題：如何正確地獲取容器中的 cpu 利用率？

在上一篇 《Linux 中的各項 CPU 利用率是這樣算出來的！》 中我們討論了 Linux 是如何計算系統的 cpu 利用率。在物理機上，使用這種方法檢視 cpu 的使用情況是沒有問題的。

但是在容器中，預設情況下 /proc/stat 是使用的宿主機的偽檔案，也就是說檢視到的是物理機的 cpu 使用情況，而不是容器本身的。那麼我們該如何才能正確地獲取到容器本身的 cpu 使用率呢？

第二個問題：容器 cpu 使用率的指標項為什麼比物理機上少了 nice/irq/softirq？

不少公司基於部署的 kubelet 解決了獲取的問題，將容器的總 cpu 用量、user 使用者態、system 系統態都正確地上報了。

但如果你仔細觀察過就會發現，是在物理機的 top 輸出中有 user/nice/system/irq/softirq 等很多指標項，而容器中卻只有 user 和 system。其它的指標項去哪兒了？

實際上，容器中統計到 cpu user、system 指標項的含義和物理機中 top 輸出的同名指標項的含義是完全不同的。

好，我們現在對以上兩個問題進行深入的剖析！

一、獲取容器 cpu 利用率的思路

絕大部分同學都習慣了使用 top 來檢視 cpu 利用率。到了容器裡，大家也都是習慣開啟 top 看看。但經常會遇到明明是 2 核的容器，top 顯示出來的核卻有很多個。

這是因為在預設情況下，容器中的 /proc/stat 並沒有單獨掛載，而是使用的宿主機的。而 top 命令中對 cpu 核數的判斷，以及對 cpu 利用率的顯示都是根據 /proc/stat 檔案的輸出來計算的。所以自然容器下想看 cpu 利用率就不能使用這種方法了。

那麼容器下就沒有辦法正確獲取 cpu 的使用情況了嗎？肯定不是的，辦法總比困難多。

第一個辦法是對容器中的 /proc/ 目錄下的一些檔案進行掛載，包括 /proc/stat。在容器中不再使用和宿主機相同的檔案。lxcfs 就是基於這種思想做出來的專案。業界有不少公司都使用它修改了容器裡的 stat 偽檔案。該專案的 github 地址： https://github.com/lxc/lxcfs

安裝了 lxcfs 後，開發們又可以愉快地像在物理上一樣地使用 top 來玩耍了。

第二個方法就是直接找到容器所屬的 cgroup 目錄，在這裡也有當前 cgroup 所消耗的 cpu 資源的統計資訊。根據這個資訊可以計算出容器的 cpu 利用率。

kubelet 中整合的 cadvisor 就是採用上述方案來上報容器 cpu 利用率的打點資訊的。每隔一段定長的時間都進行取樣，將資料上傳給 Prometheus。這樣，我們就能在 Prometheus 上看到容器的 cpu 利用資訊了。 不過 cadvisor 具體訪問 cgroup 目錄是透過呼叫 libcontainer 獲取的。 github 地址： https://github.com/opencontainers/runc/tree/main/libcontainer

如果我們自己在業務中出於某些需求需要獲取容器的 cpu 利用率的話，我建議的是採用後面的這個方法。不過要注意的是，cgroup 有 V1 和 V2 兩個版本。使用 libcontainer 的話它替我們做了這個處理。如果我們自己計算的話，需要首先判斷當前在用的 cgroup 是 V1 還是 V2。

但不管採用上面哪一個辦法，我們似乎只能把容器中 user 或者 system 的 cpu 耗時計算出來。而在宿主機中看到的 nice、irq、softirq 卻變得無影無蹤了。這一點似乎和物理機上是不一致的。

二、cgroup V2 cpu 利用率統計實現

cgroup 有 V1 和 V2 兩個版本。他們都透過偽檔案向使用者態提供了 cgroup 使用的 cpu 時間的資訊。正是有了這個基礎，我們才能夠在上一節中使用這個資料在兩個時間點之間取樣後計算 cpu 利用率。

本節我們就來看看，cgroup 提供的 cpu 使用時間資訊是怎麼來的。為了簡便，本文只以 cgroup V2 為例。

2.1 cgroup cpu 時間統計相關定義

cgroup 在核心中的定義就叫 struct cgroup。

cgroup 的 rstat_cpu 是一個 percpu 變數，對每個邏輯核都會分配一個陣列元素。 cgroup 在每個核上的使用時間資訊會先在這裡儲存。 bstat 是整個 cgroup 的全域性 cpu 使用統計。

2.2 檢視 cpu.stat 過程

在 cgroup V2 中，是透過 cpu.stat 偽檔案來檢視到容器內所有程序使用的使用者態、系統態以及彙總時間的微秒數的。

其實這個資料是來自於核心中 cgroup 物件的 bstat 成員。在這個成員中儲存了當前 cgroup 內程序所使用的使用者態時間、系統態時間以及總時間。對 cpu.stat 偽檔案的訪問就是讀取的這個資料並列印輸出的。大致流程圖如下：

開啟 cpu.stat 會觸發核心對應的處理函式 cpu_stat_show。在這個函式中會將當前 cgroup 中對每個 cpu 記錄使用率資訊彙總起來。最後轉化成微秒輸出。

我們來看下詳細工作過程。在 cgroup.c 中定義了對於 cgroup 的各個偽檔案的處理函式。

對於 cpu.stat 來說，它對應的處理函式就是 cpu_stat_show。cpu_stat_show 呼叫 cgroup_base_stat_cputime_show 訪問核心變數並列印輸出。

在這個函式中做了這麼幾件事情。

第一件，是先查詢到當前偽檔案對應的 cgroup 核心物件。 第二件，將 percpu 變數 中儲存的 cpu 時間統計彙總到全域性 bstat.cputime 中 第三件，訪問該物件的 bstat.cputime 中儲存的 utime、stime、sum_exec_runtime。 第四件，呼叫 do_div 將記憶體中的納秒值轉化成微秒，並列印輸出

我們重點來展開看下第二件事，percpu 變數的統計彙總。cgroup_rstat_flush_hold 呼叫了 cgroup_rstat_flush_locked 來進行 percpu 中 cpu 統計資訊進行彙總。

在上述函式中遍歷每個 cpu，然後呼叫 cgroup_base_stat_flush 來將該 cpu 上的記錄的 cpu 統計資訊彙總到 cgroup 的全域性統計 bstat 中。

具體的統計思路是記錄一個上一次統計資訊，本次將當前時間和上一次相減得出最近使用的 cpu 增量，然後把這些增量都呼叫 cgroup_base_stat_accumulate 累加到 cgroup 的 bstat 中。

接下來就是訪問全域性 bstat.cputime 中 utime、stime，並可能會進行一些調整，然後列印輸出。

在接下來的一個小節中我們再看下，percpu 變數 rstat 中的資料是怎麼加進來的。

2.3 累加到 percpu 統計資訊中

在《Linux 中的各項 CPU 利用率是這樣算出來的！》 中我們介紹到了，系統會定期在每個 cpu 核上發起 timer interrupt。每次當時間中斷到來的時候，取樣 cpu 使用情況並彙總起來，提供給 /proc/stat 訪問用。對於系統中每一個 cgroup 來說，也是在這個時機裡統計並彙總起來的。

定時器定時將 cgroup 在每個 cpu 上的使用資訊都記錄到 percpu 變數 rstat_cpu。我們來看看詳細的統計過程。

每次執行時鐘中斷處理程式 都會呼叫 都會呼叫 update_process_times 來進行時鐘中斷的處理。在時鐘中斷中處理的事情包括 cpu 利用率的統計，以及週期性的程序排程等。其中和容器 cpu 利用率相關的呼叫棧比較深，如下圖所示。

update_process_times 呼叫 account_process_tick 來處理 cpu 處理時間的累積。在 account_process_tick 中根據當前的狀態判斷是該累計使用者態時間，還是核心態時間。

無論是累計使用者態時間處理函式 account_user_time 還是累積核心態時間 account_system_time，最後都用呼叫到 \_\_cgroup_account_cputime_field 將當前節拍的時間新增到 cgroup 核心物件的 。

在這個函式中，將本次節拍的時間 delta_exec 新增到了 cgroup 中為統計 cpu 使用率的 percpu 變數 rstat_cpu 中了（cgroup_base_stat_cputime_account_begin 函式訪問的是 cgroup 下的 rstat_cpu）。

這裡我們還看到了，對於 user 和 nice，cgroup 都統一新增到了 utime（使用者態時間）下，對於 system、irq 和 softirq 都統計到了 stime (系統態時間)下。

這就是前面我們提到的問題的答案，為什麼容器 cpu 利用率只能體現 user 和 system，而在宿主機中可以看到的 nice、irq、softirq 卻看不到了。

這是因為容器將所有使用者態時間都記錄到了一起，系統態時間都記錄到了一起。而不像在宿主機中分的那麼細。在容器中的 cpu 的 user 指標和宿主機中 top 命令輸出的 user 指標含義是完全不一樣的，system 也是。這個點值得大家注意。在容器中：

使用者態時間：和宿主機中的 user + nice 相對應

系統態時間：和宿主機中的 system + irq + softirq 相對應。

三、總結

這篇文章中，我們討論兩個核容器 cpu 使用率相關的問題。

第一個問題：如何正確地獲取容器中的 cpu 利用率？

這個問題有兩個解決思路。

思路之一是使用 lxcfs，將容器中的 /proc/stat 替換掉。這樣 top 等命令就不再顯示的是宿主機的 cpu 利用率了，而是容器的。 思路之二是直接使用 cgroup 提供的偽檔案來進行統計，這些偽檔案一般位於 /sys/fs/cgroup/... 路徑。kubelet 中整合的 cadvisor 就是採用上述方案來上報容器 cpu 利用率的打點資訊的。

第二個問題：容器 cpu 使用率的指標項為什麼比物理機上少了 nice/irq/softirq？

這個問題的根本原因是容器 cpu 利用率的指標項 user、system 和宿主機的同名指標項根本就不是一個東西。

容器將所有使用者態時間都記錄到了 user 指標項，系統態時間都記錄到了 system。 容器中的 user 指標 ：在指標含義上等同於宿主機的 user + nice 容器中的 system 指標 ：在指標含義上等同於宿主機的 system + irq + softirq

以上就是這兩個問題的深度的答案。好了，今天的分享就到這裡，歡迎轉發！
