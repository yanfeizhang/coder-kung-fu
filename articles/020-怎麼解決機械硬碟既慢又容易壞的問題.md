# 怎麼解決機械硬碟 (Hard Disk Drive, HDD) 既慢又容易壞的問題？

> 原文標題：我们怎么解决机械硬盘既慢又容易坏的问题？

> 原文連結：https://mp.weixin.qq.com/s/n9Hf3Utm4NFp3jNRTgZNwg

---

我們使用的電腦的全稱叫電子電腦，前面有電子兩個字，這說的是整個電腦中的核心元器件基本上都是電子單元組成的。但機械硬碟卻是一個特殊的例外，它更多是用機械技術做出來的一個產品。當把帶有機械技術基因的磁碟 (Disk) 搭到電腦，尤其是再應用到伺服器領域的時候，暴露出了機械技術的兩個嚴重問題：

- 第一，速度慢。 如果把記憶體 (Memory) 和 CPU 的速度比作汽車和飛機的話，這個大哥毫秒級別的延遲幾乎就是牛車級別的。
- 第二，容易壞。 經常聽說誰誰的磁碟壞了，很少有聽說過誰的記憶體條，CPU 壞了。筆者就有在讀研期間實驗室裡正在複製資料，突然一個斷電直接廢了一塊硬碟的經歷。

要想保證伺服器運轉的穩定和高速，就必須解決硬碟從孃胎裡帶出來的這兩個缺陷。

## 多硬碟連線

問題簡單明瞭，我們要解決速度慢、容易壞兩個問題。很自然，單兵作戰不行，那我們就想到往上懟一個班，多塊硬碟一起上。但問題是，假如給你 N 塊硬碟，讓你來出一個技術方案，你會怎麼設計呢？

第一個方案就是，把一個檔案分成 N 片，每一片都雜湊在不同的硬碟上。這樣當檔案進行讀取的時候，就可以 N 塊硬碟一起來工作，從而達到讀取速度提高到 N 倍的效果，這就是 RAID 0。

不過這個方案沒有解決容易壞的問題，任何一塊硬碟壞了都會導致儲存系統故障。

第二個方案就是，仍然把檔案分片，但是所有的分片都存在一塊硬碟上，其他的硬碟只存複製。 這既提高了硬碟的存取速度，也解決了壞的問題。任意一塊硬碟壞了，儲存系統都可以正常使用，只不過速度會打一點折扣。

不過這個方案又帶來了新的問題，那就是實作成本有點高了。假如我們用 256G 硬碟想實作 512G 的儲存容量的話，最少得需要 4 塊硬碟才能實作。

有沒有折中一點的方案呢？有，而且很多。我們這裡只說下最常見的 raid5
RAID 5 同樣要對檔案進行分片，但是不對儲存的資料進行備份，而是會再單獨存一個校驗資料片。
假如檔案分為 A1 A2 A3，然後需要再存一個校驗片到別的磁碟上。這樣不管 A1，A2 還是 A3 那一片丟失了，都可以根據另外兩片和校驗片合成出來。 既保證了資料的安全性，又只用了一塊磁碟做冗餘儲存。

假如我們有 8 塊 256GB 的硬碟，那麼 RAID5 方案下的磁碟陣列從使用者角度來看可用的儲存空間是 7*256GB，只「浪費」了一塊盤的空間，所以目前 RAID5 應用比較廣泛~~

## Raid 卡快取 (Cache)

硬碟延遲是毫秒級別的，即使是多快硬碟並行，也只能提升數倍而已，不能夠達到量級的提升。和 CPU 記憶體的納秒級別工作頻率比起來，還是太慢了。
在電腦界，沒有快取解決不了的速度問題，如果有，那就再加一層。現代磁碟本身也基本都帶了快取，另外在一些比較新的 raid 卡里，硬體開發者們又增加了一層「記憶體」，並且還自己附帶一塊電池，這就是 RAID 卡快取。 我們看下幾款主流 RAID 卡的設定：

- PERC S120 入門軟體陣列卡，主機板整合無快取支援 RAID0 1
- PERC H330 入門硬體 RAID 卡，無板載快取, 支援 RAID 0 1 5 10 50
- PERC H730 主流硬體 RAID 卡帶有 1G 快取和電池支援 RAID 0 1 5 6 10 50 60
- PERC H730P 高效能硬體 RAID 卡帶有 2G 快取和電池支援 RAID 0 1 5 6 10 50 60
- PERC H830 同 H730P,沒有內建介面，使用外接介面連線附加儲存磁碟櫃用

拿目前伺服器端出鏡率比較高的 H730 和 H730P 來看，他們分別帶了 1G 和 2G 的快取卡，並且自帶電池。 電池的作用就是當發現主機意外斷電的時候，能夠快速把快取中的資料寫回到磁碟中去。對於寫入，一般作業系統 (Operating System) 寫到這個 RAID 卡里就完事了，所以速度快。對於讀取也是，只要快取裡有，就不會透傳到磁碟的機械軸上。

另外想再補充說一點的就是檔案相關函式里設定 DIRECT   `I/O` 僅僅只能繞開作業系統本身的 Page Cache,而 RAID 卡里的快取，對於 Linux 來說，可以說算是一個黑盒。換句話說，就是作業系統並不清楚 RAID 卡是從快取裡吐的資料，還是真正從硬碟裡讀的。

## 動手檢視你的 RAID 設定

瞭解了 raid 基本原理以後，我們可以實際動手檢視一下機器上的 raid 情況。這裡拿我手頭的一臺伺服器舉例。
透過 `cat` / `proc/scsi/scsi`，我們可以檢視到 raid 卡的型號

```
Host: scsi10 Channel: 02 Id: 01 Lun: 00
  Vendor: DELL     Model: PERC H730 Mini   Rev: 4.27
  Type:   Direct-Access                    ANSI  SCSI revision: 05
```

可以看到我的這臺伺服器 raid 卡使用的是 PERC H730， 這塊 RAID 卡帶有 1G 快取和電池。

再看我們的硬碟陣列

```
# /opt/MegaRAID/MegaCli/MegaCli64  -LDInfo -Lall -aALL

Virtual Drive: 1 (Target Id: 1)
Name                :
RAID Level          : Primary-5, Secondary-0, RAID Level Qualifier-3
Size                : 1.633 TB
Sector Size         : 512
Is VD emulated      : No
Parity Size         : 278.875 GB
State               : Optimal
Strip Size          : 128 KB
Number Of Drives    : 7
Span Depth          : 1
```

RAID Level 列標明的就是當前 RAID 組的 RAIN 級別。對照下面

- RAID 1:   Primary-1, Secondary-0, RAIDLevelQualifier-0 RAID 1
- RAID 0: Primary-0, Secondary-0, RAID Level Qualifier-0 RAID 0
- RAID 5:   Primary-5, Secondary-0, RAIDLevelQualifier-3 RAID 5
- RAID 10: Primary-1, Secondary-3, RAID Level Qualifier-0 RAID 10

可以看到，本機 RAID Level 是 RAID5。

另外 Strip Size 叫做條帶大小，我機器上的設定是 128KB。假如有一個 512KB 的檔案，它就會被分成 4 個條帶，每個 128KB。這些條帶可能會分散在不同的磁碟上，如果一次性讀取的話，多個硬碟就可以一起轉動機械軸，讀取速度就會提高到原來的數倍。不過要說明的是，如果檔案小於這個條帶大小，小於 128K，那麼 RAID 下的多塊硬碟對於該檔案的讀取耗時也不會有幫助。

繼續檢視組成 RAID 的所有的磁碟的狀況：


看到屬於 DiskGroup 1 的總共有 7 塊硬碟，每塊的大小都是 278GB 左右。6 塊盤的總容量大小就是 1.6T 左右，確實是只「浪費」了一塊硬碟的容量來保障資料的安全性！

另外 Inquiry Data 也顯示了硬碟的製造商，已經型號。這些磁碟都是希捷的 300G 的機械硬碟，經 Google 查詢其轉速為 1 萬轉每分鐘。

## 本文小節

機械技術和電子技術比較起來，穩定性要差很多。所以機械背景出身的硬碟既慢又容易壞。為了解決這個問題，RAID 技術應運而生。透過一定的冗餘原始儲存或者校驗資料提供安全性的保障，透過增加帶電子基因的快取，合理排程多塊磁碟的機械軸，提高了磁碟 IO 的讀寫速度。在 Linux 下可以透過 MegaCli 工具來檢視你的 RAID 組情況，強烈你建議實際動手檢視一下！
