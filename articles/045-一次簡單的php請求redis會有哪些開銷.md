# 一次簡單的 php 請求 redis 會有哪些開銷？

> 原文標題：一次简单的php请求redis会有哪些开销？

> 原文連結：https://mp.weixin.qq.com/s/yl5EuQ1wEXDuIg4E98QfZA

---

我問大家一個問題，下圖中一個最簡單的例子，會導致哪些 CPU 開銷產生？你是否能夠說清楚？

```
<?php
    ...
    $redis->get('test');
    ...
```

這個例子一下子就把大家在我的文章裡學到的東西和你的實際工作結合起來了。怎麼樣，是不是足夠簡單？就是一句 php 程式碼從 redis 執行個體中取得一個 key 的 value 值而已，相信類似的程式碼你天天都在寫。對這句 redis get 實際開銷的理解水平，就代表了你的內功的深度。

在前面的文章中介紹了一些和 CPU 相關的硬體、核心知識，把開銷大戶程序 (Process) 上下文切換 (Context Switch)、系統呼叫 (System Call)、軟中斷 (Softirq) 的具體開銷都挨個分析了一遍。不過，這時候我覺得有很多開發同學都有一個疑惑，仍然是覺得：「我是應用層的開發，這麼底層的開銷和我有什麼關係？」 或者是說：「線上伺服器的運維不都應該是運維的工作嗎？和開發又沒關係」

我想說的是，如果你只是一個初級或者中級開發工程師，這些確實沒有必要了解。但是如果你想成為一名高階、或者是資深開發工程師，那麼你應該具備大致估算你手下寫出的每一行程式碼開銷的能力，要對自己程式碼線上上的執行開銷負責！

接下來，我們就來帶大家從更深層次的方向認識到這句簡單程式碼的開銷。為了便於測試，我們對程式碼進行一些簡單的改造，最終的實際測試檔案如下。測試程式碼見 test07

```
<?php
    $redis = new Redis();
    $redis->connect({某Redis server的IP}, 6339);

    sleep(60);
    echo "Test begin\n";
    for($i=0; $i<10000; $i++){
        $redis->get('test');
    }
    echo "Test end!\n ";
    sleep(60);
```

例子非常的簡單，就是一句後端同學程式碼裡經常出現的從 Redis 裡取得了一條資料而已。那麼讓我們看看它到底會產生哪些開銷？

## 1.系統呼叫

```
# strace -c php main.php

------ ----------- ----------- --------- --------- ----------------
 97.24    0.039698           1     30003           poll
  2.20    0.000899           0     10003           sendto
```

從實際測試結果可見，每次 get 操作都需要執行多次系統呼叫才可完成。

## 2、程序上下文切換 (Process Context Switch)

每次呼叫 get 後，如果資料沒有回傳。程序都是阻塞掉的，因此還會導致程序進入主動上下文切換。 我們用實驗的方式來檢視一下：

```
# php main.php
```

然後再另起一個控制檯，分別趕在實驗開始前和實驗開始後執行如下兩行命令：

```
# grep ctxt /proc/14862/status
voluntary_ctxt_switches:        4
nonvoluntary_ctxt_switches:     43

# grep ctxt /proc/14862/status
voluntary_ctxt_switches:        10005
nonvoluntary_ctxt_switches:     49
```

每次 get 都會導致程序進入自願上下文切換，在網路 IO 密集型的應用裡自願上下文切換要比時間片到了被動切換要多的多！

## 3、軟中斷

每次在 redis 伺服器回傳資料的時候，網路卡 (Network Card) 都會透過軟中斷的方式來讓核心處理資料封包。因此

```
# cat /proc/softirqs
                CPU0       CPU1       CPU2       CPU3
      HI:          0          0          0          0
   TIMER:  196173081  145428444  154228333  163317242
  NET_TX:          0          0          0          0
  NET_RX:  178159928     116073      10108     160712


# cat /proc/softirqs
                CPU0       CPU1       CPU2       CPU3
      HI:          0          0          0          0
   TIMER:  196173688  145428634  154228610  163317624
  NET_TX:          0          0          0          0
  NET_RX:  178170212     116073      10108     160712
```

該虛機的軟中斷親和性在 CPU0 上，178170212-178159928 = 10284（多出來的 284 是機器上其他的小服務）。
每次 get 請求收到資料回傳的時候，核心必須要支出一次軟中斷的開銷！

## 總結

看似一次非常簡單的 redis get 操作就會把所有系統態的高開銷操作都涉及到了。一次程序上下文切換、一次軟中斷、若干次系統呼叫。在經過了前面多篇文章的歷練，相信大家對它們的開銷有了一個量化的拿捏。其實除了上面這些容易評估到的開銷外，還有如 L1、L2 cache miss，以及 TLB cache miss 這些在程序被切換掉都會造成 cache 命中率下降，也會導致額外開銷。

所以，你以為的簡單，其實不一定簡單！
