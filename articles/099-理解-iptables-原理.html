大家好，我是飛哥！ 現在 iptables 這個工具的應用似乎是越來越廣了。不僅僅是在傳統的防火牆、NAT 等功能出現，在今天流行的的 Docker、Kubernets、Istio 專案中也經常能見著對它的身影。正因為如此，所以深入理解 iptables 工作原理是非常有價值的事情。

Linux 核心網路棧是一個純核心態的東西，和使用者層功能是天然隔離。但為了迎合各種各樣使用者層不同的需求，核心開放了一些口子出來供使用者干預。使得使用者層可以透過一些配置，改變核心的工作方式，從而實現特殊的需求。

Linux 在核心網路元件中很多關鍵位置佈置了 netfilter 過濾器​。Iptables 就是基於 netfilter 來實現的。所以本文中 iptables 和 netfilter 這兩個名詞有時候就混著用了。​

飛哥也在網上看過很多關於 netfilter 技術文章，但是我覺得都寫的不夠清晰。所以咱們擼起袖子，自己寫一篇。Netfilter 的實現可以簡單地歸納為四表五鏈。我們來詳細看看四表、五鏈究竟是啥意思。

一、Iptables 中的五鏈

Linux 下的 netfilter 在核心協議棧的各個重要關卡埋下了五個鉤子。每一個鉤子都對應是一系列規則，以連結串列的形式存在，所以俗稱 五鏈 。當網路包在協議棧中流轉到這些關卡的時候，就會依次執行在這些鉤子上註冊的各種規則，進而實現對網路包的各種處理。

要想把五鏈理解好，飛哥認為最關鍵是要把核心接收、傳送、轉發三個過程分開來看。

1.1 接收過程

Linux 在網路包接收在 IP 層的入口函式是 ip_rcv。網路在這裡包碰到的第一個 HOOK 就是 PREROUTING。當該鉤子上的規則都處理完後，會進行路由選擇。如果發現是本裝置的網路包，進入 ip_local_deliver 中，在這裡又會遇到 INPUT 鉤子。

我們來看下詳細的程式碼，先看 ip_rcv。

NF_HOOK 這個函式會執行到 iptables 中 pre\_routing 裡的各種表註冊的各種規則。當處理完後，進入 ip_rcv_finish。在這裡函式里將進行路由選擇。這也就是 PREROUTING 這一鏈名字得來的原因，因為是在路由前執行的。

如果發現是本地裝置上的接收，會進入 ip_local_deliver 函式。接著是又會執行到 LOCAL_IN 鉤子，這也就是我們說的 INPUT 鏈。

簡單總結接收資料的處理流程是： PREROUTING鏈 -> 路由判斷（是本機）-> INPUT鏈 -> ...

1.2 傳送過程

Linux 在網路包傳送的過程中，首先是傳送的路由選擇，然後碰到的第一個 HOOK 就是 OUTPUT，然後接著進入 POSTROUTING 鏈。

來大致過一下原始碼，網路層傳送的入口函式是 ip_queue_xmit。

在這裡先進行了傳送時的路由選擇，然後進入傳送時的 IP 層函式 \_\_ip_local_out。

上面的 NF_HOOK 將傳送資料包送入到 NF_INET_LOCAL_OUT (OUTPUT) 鏈。執行完後，進入 dst_output。

在這裡獲取到之前的選路，並呼叫選到的 output 傳送。將進入 ip_output。

總結下傳送資料包流程是： 路由選擇 -> OUTPUT鏈 -> POSTROUTING鏈 -> ...

1.3 轉發過程

其實除了接收和傳送過程以外，Linux 核心還可以像路由器一樣來工作。它將接收到網路包（不屬於自己的），然後根據路由表選到合適的網絡卡裝置將其轉發出去。

這個過程中，先是經歷接收資料的前半段。在 ip_rcv 中經過 PREROUTING 鏈，然後路由後發現不是本裝置的包，那就進入 ip_forward 函式進行轉發，在這裡又會遇到 FORWARD 鏈。最後還會進入 ip_output 進行真正的傳送，遇到 POSTROUTING 鏈。

我們來過一下原始碼，先是進入 IP 層入口 ip_rcv，在這裡遇到 PREROUTING 鏈。

PREROUTING 鏈條上的規則都處理完後，進入 ip_rcv_finish，在這裡路由選擇，然後進入 dst_input。

轉發過程的這幾步和接收過程一模一樣的。不過核心路徑就要從上面的 input 方法呼叫開始分道揚鑣了。非本裝置的不會進入 ip_local_deliver，而是會進入到 ip_forward。

在 ip_forward_finish 裡會送到 IP 層的傳送函式 ip_output。

在 ip_output 裡會遇到 POSTROUTING 鏈。再後面的流程就和傳送過程的下半段一樣了。

總結下轉發資料過程：PREROUTING -> 路由判斷（不是本裝置，找到下一跳） -> FORWARD -> POSTROUTING -> ...

二、Iptables 的四表

在上一節中，我們介紹了 iptables 中的五個鏈。在每一個鏈上都可能是由許多個規則組成的。在 NF_HOOK 執行到這個鏈的時候，就會把規則按照優先順序挨個過一遍。如果有符合條件的規則，則執行規則對應的動作。

而這些規則根據用途的不同，又可以raw、mangle、nat 和 filter。

raw 表的作用是將命中規則的包，跳過其它表的處理，它的優先順序最高。

mangle 表的作用是根據規則修改資料包的一些標誌位，比如 TTL

nat 表的作用是實現網路地址轉換

filter 表的作用是過濾某些包，這是防火牆工作的基礎

在 PREROUTING 鏈中的規則中，分別可以執行 raw、mangle 和 nat 三種功能。

為什麼不是全部四個表呢，這是由於功能的不同，不是所有功能都會完全使用到五個鏈。

Raw 表目的是跳過其它表，所以只需要在接收和傳送兩大過程的最開頭處把關，所以只需要用到 PREROUTING 和 OUTPUT 兩個鉤子。

Mangle 表有可能會在任意位置都有可能會修改網路包，所以它是用到了全部的鉤子位置。

NAT 分為 SNAT（Source NAT）和 DNAT（Destination NAT）兩種，可能會工作在 PREROUTING、INPUT、OUTPUT、POSTROUTING 四個位置。

Filter 只在 INPUT、OUTPUT 和 FORWARD 這三步中工作就夠了。

Docker 容器就是基於名稱空間來工作的，所以每個 Docker 容器中都可以配置自己獨立的 iptables 規則

三、Iptables 使用舉例

看完前面兩小節，大家已經理解了四表五鏈是如何實現的了。那我們接下來透過幾個實際的功能來看下實踐中是如何使用 iptables 的。

3.1 SNAT 源地址替換

假如說我們有一臺 Linux，它的 eth0 的 IP 是10.162.0.100，透過這個 IP 可以訪問另外其它伺服器。現在我們在這臺機器上建立了個 Docker 虛擬網路環境 net1 出來，它的網絡卡 veth1 的 IP 是 192.168.0.2。

如果想讓 192.168.0.2 能訪問外部網路，則需要宿主網路名稱空間下的裝置工作幫其進行網路包轉發。由於這是個私有的地址，只有這臺 Linux 認識，所以它是無法訪問外部的伺服器的。這個時候如果想要讓 net1 正常訪問 10.162.0.101，就必須在轉發時執行 SNAT - 源地址替換。

SNAT 工作在路由之後，網路包傳送之前，也就是 POSTROUTING 鏈。我們在宿主機的名稱空間裡增加如下這條 iptables 規則。這條規則判斷如果源是 192.168.0 網段，且目的不是 br0 的，統統執行源 IP 替換判斷。

有了這條規則，我們來看下整個發包過程。

當資料包發出來的時候，先從 veth 傳送到 br0。由於 br0 在宿主機的名稱空間中，這樣會執行到 POSTROUTING 鏈。在這個鏈有我們剛配置的 snat 規則。 根據這條規則，核心將網路包中 192.168.0.2（外界不認識） 替換成母機的 IP 10.162.0.100（外界都認識）。同時還要跟蹤記錄連結狀態。

然後宿主機根據自己的路由表進行判斷，選擇預設傳送裝置將包從 eth0 網絡卡傳送出去，直到送到 10.162.0.101。

接下來在 10.162.0.100 上會收到來自 10.162.0.101​ 的響應包。由於上一步記錄過連結跟蹤，所以宿主機能知道這個回包是給 192.168.0.2 的。再反替換並透過 br0 將返回送達正確的 veth 上。

3.3 filter

Filter 表主要實現網路包的過濾。假如我們發現了一個惡意 IP 瘋狂請求我們的伺服器，對服務造成了影響。那麼我們就可以用 filter 把它禁掉。其工作原理就是在接收包的 INPUT 鏈位置處進行判斷，​發現是惡意請求就儘早幹掉不處理。避免進入到更上層繼續浪費 ​CPU 開銷。

3.5 mangle

路由器在轉發網路包的時候，ttl 值會減 1 ，該值為 0 時，最後一個路由就會停止再轉發這個資料包。如若不想讓本次路由影響 ttl，便可以在 mangel 表中加個 1，把它給補回來。

所有從 eth0 介面進來的資料包的 ttl 值加 1，以抵消路由轉發預設減的 1。
