# 揭穿記憶體 (Memory) 廠家「謊言」，實測記憶體頻寬 (Memory Bandwidth) 真實表現

> 原文標題：揭穿内存厂家“谎言”，实测内存带宽真实表现

> 原文連結：https://mp.weixin.qq.com/s/AJjBHCNPWN8YW8v0iXjjig

---

頻寬是儲存系統一個的一個非常重要的衡量指標，記憶體頻寬指的是 CPU 從記憶體讀取或寫入資料到記憶體的速率。我們今天來思考一個問題，在你的應用程式裡記憶體的存取頻寬能夠達到多少？

## 各代記憶體頻寬規格

理論上記憶體頻寬的計算公式是：Band Width = Speed * Data Width。在這個公式的基礎上，我們來看一下各代規格的記憶體頻寬表現。

從上圖來看，DDR3 代的記憶體 DDR3 代 1066 MHz 的頻寬都已經達到了 `8.5GB/s`, DDR4 代 3200MHz 更是達到了驚人的 25.6G。 廠家在進行銷售的時候也都是用這個公式來算，言外之意就是告訴你：「我家的產品非常快，大家趕快來買啊！」

廠家這麼宣傳似乎也不算錯，但是有誘導性的謊言在其中。 廠家這個資料的基礎是記憶體嚴格以順序 IO 的方式工作，而且把傳輸的記憶體位址也當資料來看，進而計算出的結果。但我們在《記憶體隨機存取也比順序慢，帶你深入理解記憶體 IO 過程》中明白了的是，記憶體在並一定是所有的 Data Speed 週期都在源源不斷往外吐資料。在 CPU 傳入了行位址後，記憶體開啟一行需要 tRCD+tRP 個時鐘週期的延遲。輸入列位址後，又需要等待 CL 個時鐘週期。而記憶體作為易失性儲存元器件，又需要定時對所有的行進行充電，來保證資料不丟失。所以，在實踐中，我們並不是總是能夠達到廠家宣傳的理論頻寬值。

> 注意：理論頻寬值計算時採用的是記憶體的 Speed，也就是其資料頻率。而記憶體的延遲呢，用的是時鐘週期。現代的記憶體在時鐘週期的上沿和下沿都可以傳輸資料，所以資料頻率比 Speed 又慢了一半。對於筆者 Speed 為 1067MHz 的記憶體條，其時脈頻率是 553MHz。

鄧爺爺說過，實踐是檢驗真理的唯一標準。我們今天就來進行一下實際的測試，看看記憶體的到底每秒能給我們吐出多少的資料。和前文《實際測試記憶體在順序 IO 和隨機 IO 時的存取延遲差異》的測試方法類似，我們今天對方法進行下小改動，用它來測試頻寬。

## 順序 IO 情況核心測試方法

測試程式碼主體上和延遲測試差不多，定義一個指定大小的陣列，然後以指定步長對其進行存取。

```
void init_data(double *data, int n){
    int i;
    for (i = 0; i < n; i++)    {
        data[i] = i;
    }
}

void seque_access(int elems, int stride) {
    int i;
    double result = 0.0;
    volatile double sink;

    for (i = 0; i < elems; i += stride) {
        result += data[i];
    }
    sink = result;
}
```

考慮到記憶體對齊 (Memory Alignment) 能提高效能，所以公平起見，我們每次都是按記憶體位寬去取的（一個 double 8 個位元組，正好是一個記憶體位寬）。頻寬就是每秒存取的位元組總數，所以我們透過如下程式碼進行計算。

```
result = total_accessed_bytes * 1000  / used_microseconds;
```

## 順序 IO 情況頻寬測試結果

筆者的伺服器上的記憶體條是 DDR3,1067MHz，延遲參數為 7-7-7-24。我們進行了多場景的測試。

場景一： 固定陣列大小 2K，調節步長

陣列為 2k，足夠小到 L1 cache 全部都能裝的下。這時候其實基本實際記憶體 IO 發生的很少，大部分都是更高效的 L1 cache 的 IO，在 CPU 內部就完成了。但最高值也才 6G 而已，也沒有達到廠家宣稱的 8GB。

場景二： 固定步長為 8，陣列從 32K 到 64M

陣列越大，Cache 越裝不下，資料存取的 IO 會更多地往後穿透到 L2、L3 和記憶體。L1、L2、L3 和記憶體 IO 的效能依次遞減，因此陣列越大，平均頻寬就會越低。

場景三： 步長為 32，陣列從 32K 到 64M

步長增加後，穿透到記憶體的次數進一步增加，頻寬進一步下降。這個時候，我們應用程式視角看到的資料頻寬已經下降到 1GB 以下了。

## 再測隨機 IO 情況

前面的測試情況，雖然步長也在變化，但都是有序遞增。這樣記憶體的連續兩次 IO 之間，雖然列位址會變，但是行位址極有可能不發生變化，因此效率還是算比較高。 我們這次是來徹底隨機進行存取，再來看一下。

隨機存取，陣列從 8K 到 64M

當陣列比較小的時候，雖然亂序存取，但是 cache 能兜住，因此記憶體 IO 實際上發生的很少。但當陣列增加到 64M 的時候，再加上哪一級 Cache 都兜不住了。再加上存取又足夠隨機，因此都穿透到了記憶體，而且行的行位址也極大可能發生變化。這時，記憶體頻寬竟然下降到了 474M。

## 結論

廠家在宣傳的記憶體頻寬資料的時候，用的是嚴格順序 IO 情況下的資料，而且把位址的傳輸也當資料算了。但是廠家不會告訴你，在實際中記憶體的頻寬並沒有你想像的那麼快，在隨機 IO 工作模式的情況下，頻寬只有 474M 而已。 現在 SSD 固態硬碟 (Solid-State Drive, SSD) 順序 IO 也差不多能達到這個數量級了。所以，我們以後不要魯莽地說記憶體比硬碟要快很多。快不快，關鍵取決於你怎麼用！
