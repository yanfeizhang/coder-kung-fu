# 我是怎麼樣寫出開發內功修煉的？秘密都在這裡！

> 原文標題：我是怎么样写出开发内功修炼的？秘密都在这里！

> 原文連結：https://mp.weixin.qq.com/s/rUWqVtoP3_f0M6ltN_1gqA

---

經常收到後臺讀者發過來同樣的問題，看完「開發內功修煉」以後覺得寫的不錯。問：「飛哥你平時是怎麼樣磨鍊自己的技術能力，並寫出這些文章的？另外可否幫推薦幾本書更系統地學習一下」。今天干脆就寫一篇文章統一回復一下。

電腦技術理論與實作並重

在開始之前，我想先多扯幾句關於在電腦技術上的一點淺薄的理解。電腦技術不同於其他學科，它對理論和實踐都有較高的要求。我覺得最有用的成長方式就是理論和實踐結合起來。用鄧爺爺的話說就是兩手抓，兩手都要硬。

如果你還是學生，大機率理論佔比會過於偏多，你就需要加強你的實踐。要多多動手，甚至可以考慮去參加一些專案，在專案中不斷實踐自己學到的理論知識。這麼做的好處是你不僅是有了實踐經驗，而且對你掌握的理論知識的認識也會進一步加深。

如果你已經工作了，可能手頭的工作幹了很多。那可能需要暫停下手頭機械搬磚的動作，結合自己的工作思考一下，工作中有哪些地方自己理論理解深度還不夠，限制了你將手頭工作推向更高的層次。回頭去好好深耕理論，進而再將自己的工作做到更好的水平。

我的技術成長故事

我個人是屬於已經工作了的那一類。我在日常 code 之餘會有節奏有目的地推進自己的理論思考。沒錯，我用的字眼不是學習，而是思考。我對工作中看似司空見慣的問題發起疑問，然後自己花時間去翻閱各種資料，進行深度思考，然後將相關理論知識再次進行測試驗證，最後在專案中應用。

例如有一次我們自己維護了一個線上的 redis（當時工程部還沒有 redis 平臺，redis 服務要業務自己維護）。為了最佳化效能，我把後端的請求由短連線改成了長連線。雖然看效果效能確實是最佳化了，但是我的思考並沒有停止。我們所有的後端機都會連線這個 redis。這樣在這個 redis 執行個體上可能得有 6000 多條併發連線存在。我就開始疑惑，Linux 最多能有多少個 TCP 連線呢，我這 6000 條長連線會不會把這個伺服器玩壞？

所以我去回頭翻各種資料，尤其是核心相關的。上網查各種文章，並進行多次的實踐測試以後終於把這塊的理論徹底理解了。我的這篇文章《漫畫 | 一臺 Linux 伺服器最多能支撐多少個 TCP 連線？》 就是這麼來的。這個深度的理解對我後續的工作有極大幫助~~

我的類似的思考有很多。例如後端的各種服務經常要進行壓測，經常會提及效能瓶頸。我又在想，整個電腦體系結構裡，各個模組的效能表現究竟是什麼樣的。例如記憶體 (Memory) 的延遲是多少，頻寬能達到多少，真有廠家吹的那麼厲害？經過思考以及動手測試後，下面幾篇文章就誕生了

《實際測試記憶體在順序 IO 和隨機 IO 時的存取延遲差異》
《揭穿記憶體廠家「謊言」，實測記憶體頻寬 (Memory Bandwidth) 真實表現》
《搭載固態硬碟 (Solid-State Drive, SSD) 的伺服器究竟比搭機械硬碟 (Hard Disk Drive, HDD) 快多少？》

所有我這些思考成果彙總出來就形成了現在的「開發內功修煉」

當你開始深度思考一個具體問題的時候，你可能會發現，其實大部分時候沒有任何一本現成的技術書籍能有完整的答案。例如我當時想查詢記憶體的延遲，頻寬效能的時候，想看下記憶體的整體工作原理、CL、CD 等各種延遲究竟是什麼含義。我翻遍了手頭的資料也沒找到靠譜的結論，後來是在幾本書、加上網際網路 (Network) 上搜來了幾個零星的資料、再加上親手實踐測試後才算是徹底理解的。

這種對理論知識進行深度思考再加動手驗證以後得來的知識在腦子裡的印象特別深的。你幾乎不太可能忘了它，因為它已經徹底內化到你的知識體系裡了。在網際網路時代，各種各樣的知識取得成本已經足夠的低，但只有深度思考才能讓你把取得來的知識有機地組織，徹底融合到你的技能堆疊中。

高效學習方法總結

不過我最後再次強調一下我本人的核心修煉方法。我並不完全是用的傳統的學習方法 - 挨本經典書都啃一遍或多遍。原因第一是工作後沒有那麼多的大塊時間。第二是這種方法學來的東西很難內化到你自己的技術堆疊上，只是淺度的學習而已。

我的學習方法總結起來就是三步曲：

1. 保持好奇心發現問題

在工作中，每一個司空見慣，不起眼的地方可能都會引發我的思考。每一個有意無意的小問題可能都不會被我放它過去。空檔案佔用多少磁碟 (Disk) 空間，我非得去看看。檔名存到哪裡去了，我非得查個究竟。明明線上將長連線改成短連線效能已經最佳化過了，效果已經出來了。我還不行，我非得測測一臺伺服器究竟能撐多少條連線！

2. 帶著問題去深度思考、去查各種資料

每當我工作中遇到疑惑的時候，我都會把相關的經典書先翻開再查一遍。很多時候，書裡的內容也並不能完整解釋我的疑惑，例如上面我推薦的經典裡沒有任何一本書能清楚介紹記憶體是怎麼工作的，網路封包 (Network Packet) 是怎麼經過網路卡 (Network Card) 到用的程序 (Process) 裡的。我就還會繼續 Google 上搜各種資料，甚至必要的時候也會翻開 Linux 的原始碼。

3. 別偷懶，加上動手實測

在理論上得到初步解釋以後，其實這個時候你只是初步理解了，但理解深度還遠遠不夠。而且還有可能是你查到的資料是片面的，甚至有可能都是錯的。這時候的動手實際測試顯得尤為重要，用各種效能測試工具也可以，自己直接親手寫一段程式碼也 ok。反正就要用實踐檢驗理論是否正確。不正確的時候，再去別的地方搜其他的解釋。如此往復迭代，直到把疑惑徹底消滅掉為止~

總之，不要放過你手頭工作中任何一個不起眼的疑問，抓住它進行深度思考，然後別偷懶多動手。當把問題真正理解透徹的時候，你會得到特別特別特別大的進步。
