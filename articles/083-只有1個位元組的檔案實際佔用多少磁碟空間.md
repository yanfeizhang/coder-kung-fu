# 只有1個位元組的檔案實際佔用多少磁碟空間

> 原文標題：只有1个字节的文件实际占用多少磁盘空间

> 原文連結：https://www.cnblogs.com/kfngxl/p/13929792.html

---

在前文《新建一個空檔案是否佔用磁碟空間？佔用多少》中我們瞭解到了一個空檔案的磁碟開銷。
今天我們再思考另外一個問題，假如我們給檔案裡只寫入1個位元組，那麼這個檔案實際的磁碟佔用也是1個位元組嗎？

## 檢視1個位元組的檔案

和前文一樣，先不談原理，直接動手操作。

```
# mkdir tempDir
# cd tempDir
# du -h
0    .
# touch test
# du -h
0    .
```

在一個目錄中建立了一個空的檔案以後，透過`du`命令看到的該資料夾的佔用空間並沒有發生變化。這倒是符合我們之前的認識，因為空檔案只佔用inode。好，那讓我們修改檔案，新增一個字母

```
echo "a" > test
# du -h
4.0K    .
```

儲存後再次檢視該目錄的空間佔用。我們發現由原來的0增加到了4K。
所以說，檔案裡的內容不論多小，哪怕是一個位元組，其實作業系統也會給你分配4K的。哦，當然了還得再算前文中說到的inode和資料夾資料結構中儲存的檔名等所用的空間。
所以，不要在你的系統裡維護一大堆的碎檔案。檔案再小，佔用磁碟其實一點都不少！

> 注意我的實驗環境是在ext檔案系統下進行的。如果是xfs可能表現會有些許出入。

## 繼續討論這個4K

再把linux原始碼檔案fs/ext2/ext2.h裡關於inode的定義翻出來，我們找到結構體中定義的指向資料節點用的block陣列：

```
struct ext2_inode {
        ......
        __le32  i_block[EXT2_N_BLOCKS]; # 指向儲存檔案資料的塊的陣列
        ......
```

當檔案沒有資料需要儲存的時候，這個陣列都是空值。而當我們寫入了1個位元組以後，檔案系統就需要申請block去儲存了，申請完後，指標放在這個陣列裡。哪怕檔案內容只有一個位元組，仍然會分配一個整的Block，因為這是檔案系統的最小工作單位。那麼這個block大小是多大呢，ext下可以透過`dumpe2fs`檢視。

```
#dumpe2fs -h /dev/mapper/vgroot-lvroot
......
Block size:               4096
```

在我的機器上，一個Block是4KB。

## 檔案內容再大了怎麼辦

不知道你留意沒，inode中定義的block陣列大小呢，只有`EXT2_N_BLOCKS`個。我們再檢視一下這個常量的定義，發現它是15，相關核心中定義如下：

```
#define EXT2_NDIR_BLOCKS                12
#define EXT2_IND_BLOCK                  EXT2_NDIR_BLOCKS
#define EXT2_DIND_BLOCK                 (EXT2_IND_BLOCK + 1)
#define EXT2_TIND_BLOCK                 (EXT2_DIND_BLOCK + 1)
#define EXT2_N_BLOCKS                   (EXT2_TIND_BLOCK + 1)
```

就按4K的block size來看，15個block只夠存的下15*4=60K的檔案。 這個檔案大小相信你一定不滿意，你存一個avi大片都得上G了。那Linux是怎麼實現大檔案儲存的呢？嗯，其實上面宏的定義過程已經告訴你了，就是隻有12個陣列直接存block指標，其餘的用來做間接索引（EXT2_IND_BLOCK），二級間接索引（EXT2_DIND_BLOCK）和三級索引（EXT2_TIND_BLOCK）。

這樣，一個檔案可以使用的空間就指數倍的擴充套件了。 檔案小的時候，都用直接索引，磁碟IO少，效能好。檔案大的時候，訪問一個block可能得先進行三次的IO，效能略慢，不過有OS層面的頁快取、目錄項快取的加持，也還好。

## 結論

檔案系統是按照塊來管理的，所以不管你的檔案多小，哪怕只有一個位元組，都會消耗掉整整一個塊。這個塊大小可以透過`dumpe2fs`等命令來檢視。如果想改變這個塊大小怎麼辦?對不起，只能重新格式化。
