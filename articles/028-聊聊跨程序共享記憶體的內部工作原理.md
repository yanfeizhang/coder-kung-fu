# 聊聊跨程序 (Process) 共享記憶體 (Memory) 的內部工作原理

> 原文標題：聊聊跨进程共享内存的内部工作原理

大家好，我是飛哥！

在 Linux 系統的程序虛擬記憶體 (Virtual Memory) 中，一個重要的特性就是不同程序的位址空間是隔離的。A 程序的位址 0x4000 和 B 程序的 0x4000 之間沒有任何關係。這樣確確實實是讓各個程序的執行時互相之間的影響降到了最低。某個程序有 bug 也只能自己崩潰，不會影響其他程序的執行。

但是有的時候我們是想要跨程序傳遞一些資料的。因為程序虛擬記憶體位址是隔離的。所以目前業界最常用的做法是讓程序之間透過 127.0.0.1 或者是 Unix Domain   `Socket` 等本機網路 (Network) 手段進行資料的傳輸。這個方案在傳輸的資料量較小的時候工作是很不錯的。

但如果程序間想共享的資料特別大，例如說幾個 GB，那如果使用網路 IO 方案的話，就會涉及到大量的記憶體複製的開銷，導致比較低的程式效能。這是可以採用程序間共享記憶體的方法來在通訊時避免記憶體複製。

那麼問題來了，不同程序之間的虛擬位址是隔離的，共享記憶體又是如何突破這個限制的呢？我們今天就來深入地瞭解下共享記憶體的內部工作原理。

## 一、共享記憶體的使用方式

共享記憶體傳送方程序的開發基本過程是呼叫 `memfd_create` 建立一個記憶體檔案。然後透過 `mmap` 系統呼叫 (System Call) 為這個記憶體檔案申請一塊共享記憶體。然後這個記憶體檔案就可以寫入資料了。最後把這個檔案的控制程式碼透過 Unix Domain `Socket` 的方式給接收方程序傳送過去。

下面是傳送方的核心程式碼。

```
int main(int argc, char **argv) {
    // 建立記憶體檔案
    fd = memfd_create("Server memfd", ...);

    // 為記憶體檔案申請 MAP_SHARED 型別的記憶體
    shm = mmap(NULL, shm_size, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);

    // 向共享記憶體中寫入資料
    sprintf(shm, "這段內容是儲存在共享記憶體裡的，接收方和傳送方都能根據自己的fd存取到這塊內容");

    // 把共享記憶體檔案的控制程式碼給接收方程序傳送過去
    struct msghdr msgh;
    *((int *) CMSG_DATA(CMSG_FIRSTHDR(&msgh))) = fd;
    sendmsg(conn, &msgh, 0);
    ......
}
```

共享記憶體接收方的工作過程是先用 Unix Domain `Socket` 連線上伺服器，然後使用 recvmsg 就可以收到傳送方傳送過來的檔案控制程式碼。

```
int main(int argc, char **argv) {
    // 透過 Unix Domain Socket 連線傳送方
    connect(conn, (struct sockaddr *)&address, sizeof(struct sockaddr_un));

    // 透過連線取出傳送方傳送過來的記憶體檔案控制程式碼
    int size = recvmsg(conn, &msgh, 0);
    fd = *((int *) CMSG_DATA(cmsgh));

    // 讀取共享檔案中的內容
    shm = mmap(NULL, shm_size, PROT_READ, MAP_PRIVATE, fd, 0);
    printf("共享記憶體中的檔案內容是: %s\n", shm);
    ......
}
```

這樣這兩個程序都各自有一個檔案控制程式碼，在底層上是指向同一個記憶體檔案的。這樣就實作了傳送方和接收方之間的記憶體檔案共享了。

但我們上面介紹的是開發基本過程。按照我們本文的風格，這還不算完，我們是要把它最底層的原理真正的弄通透才算的。所以接下來我們再深入地分析   `memfd_create`、`mmap`、以及 Unix Domainsocket sendmsg 和 recvmsg 的底層工作原理，來看看它們是如何配合來實作跨程序共享記憶體的。

## 二、共享記憶體檔案原理

在傳送方傳送檔案之前，需要先透過  `memfd_create` 來建立一個記憶體檔案，然後再使用 `mmap` 為其分配記憶體。

## 2.1 建立記憶體檔案

其中  `memfd_create` 函式是一個系統呼叫。核心中它的主要邏輯有兩個，一是呼叫 `get_unused_fd_flags` 申請一個沒使用過的檔案控制程式碼，二是呼叫 `shmem_file_setup` 建立一個共享記憶體檔案。

我們來看 `memfd_create` 的原始碼。

```
// file:mm/memfd.c
SYSCALL_DEFINE2(memfd_create,
        const char __user *, uname,
        unsigned int, flags)
{
    ...
    // 申請一個未使用過的檔案控制程式碼
    fd = get_unused_fd_flags((flags & MFD_CLOEXEC) ? O_CLOEXEC : 0);

    // 建立一個共享記憶體的檔案
    file = shmem_file_setup(name, 0, VM_NORESERVE);

    fd_install(fd, file);
    return fd;
}
```

其中在 `shmem_file_setup` 函式中又呼叫了 \_\_shmem_file_setup。

```
// file:mm/shmem.c
static struct file *__shmem_file_setup(struct vfsmount *mnt, const char *name, ...)
{
    ...
    // 申請一個 inode
    inode = shmem_get_inode(mnt->mnt_sb, NULL, S_IFREG | S_IRWXUGO, 0,
                flags);
    inode->i_flags |= i_flags;
    inode->i_size = size;

    ...
    // 建立一個檔案
    res = alloc_file_pseudo(inode, mnt, name, O_RDWR,
                &shmem_file_operations);
    return res;
}
```

我們都知道磁碟 (Disk) 檔案在核心的實作中是由 inode 和 struct file 物件一起組成的。其實共享記憶體檔案也一樣，\_\_shmem_file_setup 中就是先申請了一個 inode，然後再呼叫   `alloc_file_pseudo` 建立一個檔案。值得注意的是，這個檔案並非是磁碟上的檔案，而只是在記憶體裡的。

## 2.2 `mmap` 申請記憶體

`mmap` 也是一個系統呼叫，注意我們在開篇處呼叫它的時候傳入的第三個 flag 參數是 `MAP_SHARED`。這表示的是要透過 `mmap` 申請一塊跨程序可共享的記憶體出來。 `mmap` 的實作入口在 `arch/x86/kernel/sys_x86_64.c`

```
//file:arch/x86/kernel/sys_x86_64.c
SYSCALL_DEFINE6(mmap, unsigned long, addr, ...)
{
    return ksys_mmap_pgoff(addr, len, prot, flags, fd, off >> PAGE_SHIFT);
}
```

接下來的這個函式的呼叫鏈路如下

```
SYSCALL_DEFINE6(mmap
```

- > `ksys_mmap_pgoff`
- --> `vm_mmap_pgoff`
- -----> `do_mmap_pgoff`
- -------> `do_mmap`

在   `do_mmap` 函式中，對輸入的 `MAP_SHARED` 進行了處理。

```
//file:mm/mmap.c
unsigned long do_mmap(struct file *file, unsigned long addr,
            unsigned long len, unsigned long prot,
            unsigned long flags, vm_flags_t vm_flags,
            unsigned long pgoff, unsigned long *populate,
            struct list_head *uf)
{
    struct mm_struct * mm = current->mm;
    ...

    // 如果包含 MAP_SHARED，則對要申請的虛擬記憶體設定一個 VM_SHARED
    switch (flags & MAP_TYPE) {
        case MAP_SHARED:
        case MAP_SHARED_VALIDATE:
            vm_flags |= VM_SHARED | VM_MAYSHARE;
            ...
    }
    ...

    addr = mmap_region(file, addr, len, vm_flags, pgoff, uf);
    ......
}
```

如果 flag 包含了   `MAP_SHARED`，則對要申請的虛擬記憶體設定一個 `VM_SHARED`。該標記指明的是要申請一個可以跨程序共享的記憶體塊。接下來進入 `mmap_region` 中申請虛擬記憶體。

```
//file:mm/mmap.c
unsigned long mmap_region(struct file *file, ...)
{
    struct mm_struct *mm = current->mm;
    ......

    // 申請虛擬記憶體vma
    vma = vm_area_alloc(mm);

    // vma初始化
    vma->vm_start = addr;
    vma->vm_end = addr + len;
    vma->vm_flags = vm_flags;
    vma->vm_page_prot = vm_get_page_prot(vm_flags);
    vma->vm_pgoff = pgoff;
    ......

    // 加入到程序的虛擬記憶體 vma 連結串列中來
    vma_link(mm, vma, prev, rb_link, rb_parent);
}
```

程序的虛擬記憶體位址空間在核心底層中就是由這樣一個個的 vma 來組成的。每一個 vma 都宣告的是程序虛擬位址中的某一段位址範圍已經分配出去了。在   `mmap_region` 函式中申請了 vma，並在核心中將其管理了起來。

這裡注意我們在申請共享記憶體的時候，給 vma 是帶了 `VM_SHARED` 標記的。帶了這個標記的 vma 和普通的虛擬記憶體不一樣。

後面在發生缺頁中斷 (Page Fault) 申請實體記憶體 (Physical Memory) 的時候，在不同的程序間是可以對應到同一塊實體記憶體的。所以可以實作程序間的共享。

所以真正讓程序之間可以共享記憶體的是這個帶   `VM_SHARED` 的 vma。

## 三、傳送方傳送檔案控制程式碼

傳送方在使用 `memfd_create` 建立出來記憶體檔案，並用 `mmap` 為其申請可跨程序共享的記憶體後。接著就可以透過 Unix Domain `Socket` 中對應的 sendmsg 方法將這個共享記憶體檔案的控制程式碼傳送出來。如下是傳送的程式碼範例。

```
static void send_fd(int conn, int fd) {
struct msghdr msgh;
struct iovec iov;
...

// 把檔案控制程式碼放到訊息中來
```

// 傳送出去
sendmsg(conn, &msgh, 0);
}

sendmsg 又是一個核心提供的系統呼叫，它位於 `net/socket.c` 檔案中。

```
//file:net/socket.c
SYSCALL_DEFINE3(sendmsg, int, fd, struct user_msghdr __user *, msg, unsigned int, flags)
{
    return __sys_sendmsg(fd, msg, flags, true);
}
```

該函式的呼叫路徑如下

```
SYSCALL_DEFINE3(sendmsg, ...)
```

- > __sys_sendmsg
- --> ___sys_sendmsg
- ----> ____sys_sendmsg
- ------> `sock_sendmsg`
- --------> `sock_sendmsg_nosec`
- ----------> `unix_stream_sendmsg`

在 `unix_stream_sendmsg` 中執行了真正的傳送。

```
//file:net/unix/af_unix.c
static int unix_stream_sendmsg(struct socket *sock, struct msghdr *msg, ...)
{
    // 把檔案描述符指向的檔案資訊複製到 scm_cookie 中
    struct scm_cookie scm;
    scm_send(sock, msg, &scm, false);

    // 不斷構建資料封包傳送，直到傳送完畢
    while (sent < len) {
        // 申請一塊快取區
        skb = sock_alloc_send_pskb(sk, size - data_len, data_len,
                       msg->msg_flags & MSG_DONTWAIT, &err,
                       get_order(UNIX_SKB_FRAGS_SZ));

        // 複製資料到 skb
        err = unix_scm_to_skb(&scm, skb, !fds_sent);
        err = skb_copy_datagram_from_iter(skb, 0, &msg->msg_iter, size);

        // 直接把 skb 放到對端的接收佇列中
        skb_queue_tail(&other->sk_receive_queue, skb);

        //傳送完畢回呼
        other->sk_data_ready(other);
        sent += size;
        ...
    }
}
```

在   `unix_stream_sendmsg` 中申請了個 `skb` 快取 (Cache) 區，然後把要傳送的檔案控制程式碼等資料都塞到裡面，最後呼叫 `skb_queue_tail` 直接把 `skb` 放到 Unix DomainSocket 連線另一端的接收佇列中了。

這裡注意檔案控制程式碼只有在當前程序內才是有意義的。如果直接傳送 fd 出去，接收方是沒有辦法使用的。所以在 `scm_send` 函式中，重要的邏輯是把 fd 對應的 struct file 的指標給找了出來，放到待傳送的資料裡面了。只有 file 這種核心級的物件接收方才能使用。

`scm_send`

- --> `scm_fp_copy`

在 `scm_fp_copy` 中根據 fd 把 file 給找了出來。它的指標會被放到傳送資料中

```
//file:net/core/scm.c
static int scm_fp_copy(struct cmsghdr *cmsg, struct scm_fp_list **fplp)
{
    ...
    //把每一個要傳送的 fd 對應的 file 給找出來
    for (i=0; i< num; i++)
    {
        int fd = fdp[i];
        struct file *file;

        if (fd < 0 || !(file = fget_raw(fd)))
            return -EBADF;
        *fpp++ = file;
        fpl->count++;
    }
}
```

## 四、接收方接收檔案

接下來接收方就可以透過 recvmsg 來接收傳送方傳送過來的檔案了。recvmsg 系統會呼叫到   `unix_stream_read_generic` 中，然後在這個函式中把 `skb` 給取出來。

下面是接收函式核心 `unix_stream_read_generic` 的原始碼。

```
//file:net/unix/af_unix.c
static int unix_stream_read_generic(struct unix_stream_read_state *state,
                    bool freezable)
{
    do {
        // 拿出一個 skb
        last = skb = skb_peek(&sk->sk_receive_queue);
        ...
    }
    ...
    if (state->msg)
        scm_recv(sock, state->msg, &scm, flags);
    return copied ? : err;
}
```

在 `skb` 拿出來後，還需要呼叫   `scm_recv` 來把 `skb` 中包含的檔案給找出來。在 `scm_recv` 中呼叫 `scm_detach_fds`。

```
//file:net/core/scm.c
```

在 `scm->fp->fp`[i] 中包含的是傳送方傳送過來的 struct file 指標。這樣檔案就取出來了。當然 struct file 是個核心態 (Kernel Mode) 的物件，使用者沒有辦法使用。所以還需要再為其在新的程序中申請一個檔案控制程式碼，然後回傳。

## 五、總結

共享記憶體傳送方程序的開發過程基本分   `memfd_create` 建立記憶體檔案、`mmap` 申請共享記憶體、Unix DomainSocket 傳送檔案控制程式碼三步。

- 第一步， `memfd_create` 系統呼叫的主要邏輯有兩個，一是呼叫 `get_unused_fd_flags` 申請一個沒使用過的檔案控制程式碼，二是呼叫 `shmem_file_setup` 建立一個共享記憶體檔案。
- 第二步， `mmap` 系統呼叫在呼叫它的時候傳入的第三個 flag 參數是 `MAP_SHARED`，該參數是申請一塊跨程序可共享存取的實體記憶體。
- 第三步，接著透過 Unix Domain  `Socket` 中對應的 sendmsg 方法將這個共享記憶體檔案的控制程式碼傳送出去。在傳送時，把檔案控制程式碼對應的 struct file 指標找到並放到要封裝的 `skb` 資料封包中了。

接收方程序的主要實作原理是 recvmsg 系統呼叫。在這個系統呼叫中，核心會把傳送方傳送過來的 struct file 指標取出來，然後再在當前程序下為其申請一個新的檔案控制程式碼。這個檔案控制程式碼回傳給使用者程序後，使用者程序就可以用它來和另外一個程序共享地存取同一塊記憶體了。

總體來看，共享記憶體本質上共享的是核心物件 struct file，透過在不同的程序之間使用同一個 struct file 來實作的共享。當然也得需要在虛擬記憶體物件 vma 帶上 `VM_SHARED` 標記來支援。
