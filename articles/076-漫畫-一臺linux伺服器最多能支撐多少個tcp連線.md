## 困惑很多人的併發問題

在網路 (Network) 開發中，我發現有很多同學對一個基礎問題始終是沒有徹底理解。那就是一臺伺服器最大究竟能支援多少個網路連線？我想我有必要單獨發一篇文章來好好說一下這個問題。

很多同學看到這個問題的第一反應是 65535。原因是：「聽說埠號最多有 65535 個，那長連線就最多保持 65535 個了」。是這樣的嗎？還有的人說：「應該受 TCP 連線裡四元組的空間大小限制，算起來是 200 多萬億個！」

如果你對這個問題也是理解的不夠徹底，那麼今天講個故事講給你聽！

## 一次關於伺服器端併發的聊天

> "TCP 連線四元組是源 IP 位址、源埠、目的 IP 位址和目的埠。任意一個元素髮生了改變，那麼就代表的是一條完全不同的連線了。拿我的 Nginx 舉例，它的埠是固定使用 80。另外我的 IP 也是固定的，這樣目的 IP 位址、目的埠都是固定的。剩下源 IP 位址、源埠是可變的。所以理論上我的 Nginx 上最多可以建立 2 的 32 次方（ip 數）×2 的 16 次方（port 數）個連線。這是兩百多萬億的一個大數字！！"

> "程序 (Process) 每開啟一個檔案（linux 下一切皆檔案，包括   `socket`），都會消耗一定的記憶體 (Memory) 資源。如果有不懷好心的人啟動一個程序來無限的建立和開啟新的檔案，會讓伺服器崩潰。所以 linux 系統出於安全形度的考慮，在多個位置都限制了可開啟的檔案描述符 (File Descriptor) 的數量，包括系統級、使用者級、程序級。這三個限制的含義和修改方式如下："

- 系統級：當前系統可開啟的最大數量，透過 fs.file-max 參數可修改
- 使用者級：指定使用者可開啟的最大數量，修改/  `etc/security/limits.conf`
- 程序級：單個程序可開啟的最大數量，透過 fs.nr_open 參數可修改

> "我的接收快取 (Cache) 區大小是可以設定的，透過 `sysctl` 命令就可以檢視。"

```
$ sysctl -a | grep rmem
net.ipv4.tcp_rmem = 4096    87380    8388608
net.core.rmem_default = 212992
net.core.rmem_max = 8388608
```

> "其中在   `tcp_rmem`"中的第一個值是為你們的 TCP 連線所需分配的最少位元組數。該值預設是 4K，最大的話 8MB 之多。也就是說你們有資料傳送的時候我需要至少為對應的 `socket` 再分配 4K 記憶體，甚至可能更大。"

> "TCP 分配傳送快取區的大小受參數 net.ipv4.tcp_wmem 設定影響。"

```
$ sysctl -a | grep wmem
net.ipv4.tcp_wmem = 4096    65536    8388608
net.core.wmem_default = 212992
net.core.wmem_max = 8388608
```

> "在 net.ipv4.tcp_wmem"中的第一個值是傳送快取區的最小值，預設也是 4K。當然瞭如果資料很大的話，該快取區實際分配的也會比預設值大。"

## 伺服器端百萬連線達成記

> 「準備什麼呢，還記得前面說過 Linux 對最大檔案物件數量有限制，所以要想完成這個實驗，得在使用者級、系統級、程序級等位置把這個上限加大。我們實驗目的是 100W，這裡都設定成 110W，這個很重要！因為得保證做實驗的時候其他基礎命令例如 ps，vi 等是可用的。「

活動連線數量確實達到了 100W：

```
$ ss -n | grep ESTAB | wc -l
1000024
```

當前機器記憶體總共是 3.9GB，其中核心 Slab 佔用了 3.2GB 之多。 MemFree 和 Buffers 加起來也只剩下 100 多 MB 了：

```
$ cat /proc/meminfo
MemTotal:        3922956 kB
MemFree:           96652 kB
MemAvailable:       6448 kB
Buffers:           44396 kB
......
Slab:          3241244KB kB
```
