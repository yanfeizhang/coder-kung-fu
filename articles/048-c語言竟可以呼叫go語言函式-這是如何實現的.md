# C語言竟可以呼叫Go語言函式，這是如何實現的？

> 原文標題：C语言竟可以调用Go语言函数，这是如何实现的？

> 原文連結：http://kfngxl.cn/index.php/archives/810/

---

大家好，我是飛哥！

今天和大家聊一個問題，一門語言是否可以在同一個程序內呼叫另外一門語言實現的函式？例如 C 語言是否可以呼叫 Golang 實現的函式？注意我說的是同程序內呼叫，跨程序的 IPC、PRC 之類的技術不算。

直接丟擲這個問題的答案，同程序跨語言呼叫是可行的。在各種語言設計時，為了複用其它語言生態中積累下來的大量的程式碼資產，都會實現跨語言呼叫的機制。例如在 Golang 中，實現了 cgo 機制來允許 Golang 和 C / C++ 互相呼叫。在 Java 中，允許透過 JNI 機制來呼叫 C / C++。

本文就以 C 呼叫 Golang 為例，來帶大家瞭解下跨語言呼叫的底層實現原理。

### 一、C 呼叫 Go 函式的例子

一個 C 呼叫 Go 的程式實現大致可以分為下面三個步驟：

- 第一步：使用 Golang 定義和實現一個函式

- 第二步：將 Golang 程式碼編譯成一個靜態/動態連結庫

- 第三步：在 C 語言中呼叫該靜態/動態連結庫

我們先來看一個最簡單的例子，看看 C 語言呼叫 Go 函式該如何使用的。

#### 1.1 Go 函式定義和實現

我們先用 Golang 來定義和實現一個最簡單的加法函式。

```
package main

//int add(int a, int b);
import "C"

//export add
func add(a, b C.int) C.int {
    return a + b
}

func main() {
}
```

上面的程式碼中，雖然程式碼不長，但有好幾個需要注意的地方：

- import "C" 這行表示是使用 CGO 特性。有了這一行程式碼，go build 命令會在編譯和連結階段啟動 gcc 編譯器。

- `//int add(int a, int b)`。這一行其實不是註釋，是正常的 C 語言的程式碼，宣告瞭一個 add 函式。

- add 函式實現上面的 export add。這是在將 add 函式匯出，否則外部無法呼叫它。

- add 函式中的引數型別，只能使用 C.int。這是因為不同語言的資料型別是可能有細微差異的，必須使用標準的 cgo 資料型別才可以正常通訊。

#### 1.2 將 Go 程式碼編譯成庫

接下來需要將 Go 寫的函式編譯成一個靜態/動態庫。我們採用 go build 來編譯。

```
# go build -buildmode=c-shared -o libadd.dylib main.go
```

在上述命令中，

- -buildmode=c-shared 指的是要把 go 程式碼編譯成動態連結庫。如果想編譯成靜態連結庫，則使用 -buildmode=c-archive。

- -o libadd.dylib 是指定編譯生成的動態庫名。由於我使用是 mac，所以動態連結庫的檔案字尾是 dylib。

執行上述命令後，go 編譯器會將 go 原始碼編譯後生成一個標頭檔案 libadd.h，還有一個包含 add 函式二進位制程式碼的動態庫，這個函式滿足 C 語言呼叫約定的。庫的格式在 mac 下是 libadd.dylib(在 linux 下是 libadd.so)。

#### 1.3 C 語言呼叫庫中函式

接著我們再寫一小段簡單的 C 語言程式碼，來呼叫動態庫中的 add 函式。

```
#include <stdio.h>
#include "libadd.h"

int main(void)
{
    int ret = add(2,3);
    printf("C呼叫Go函式2+3= %d", ret);
    return 0;
}
```

在這個 C 語言函式中，把libadd.h 標頭檔案引用一下，就可以使用 add 函式了。

然後編譯和連結這個程式。注意使用 -L 選項指定要連結的庫的位置。-l 選項指定要連結的庫的名字，連結器會尋找以 libxxx 為名的動態庫。

```
# gcc main.c -L. -ladd -o main
```

編譯完後，會生成一個可執行檔案 main。執行該檔案，發現 C 呼叫 Go 函式 add 成功！！

```
# ./main
C呼叫Go函式2+3=5
```

### 二、C 呼叫 Go 函式實現原理

只說技術如何使用不講原理，從來都不是咱們「開發內功修煉」的風格。在這一節中，我們來深入瞭解下 C 呼叫 Go
函式內部是如何實現的。

#### 2.1 cgo 編譯工具

幸運的是，cgo 編譯工具不但可以勝任編譯工作，還把編譯過程的中間檔案也能展示出來。這對大家理解其內部工作方式非常有幫助。

我們用 cgo 來生成一下中間編譯過程檔案

```
# go tool cgo main.go
```

cgo 首先會為每個包含`import "C"`指令的 go 原始檔生成兩個中間檔案。我們使用的檔名是 main.go，所以生成的檔名是 main.cgo1.go、main.cgo2.c。

接著對會整個 main 包生成一個 \_cgo_gotypes.go，這裡麵包含了 Go 語言一些輔助程式碼。

最後會生成包含匯出的 C 語言 add 的入口函式以及其標頭檔案，\_cgo_export.c 和 \_cgo_export.h。

生成的檔案都放在 \_obj 目錄下。

```
# ll _obj
-rw-r--r--   1 ...  2216  4 22 08:35 _cgo_.o
-rw-r--r--   1 ...  1090  4 22 08:35 _cgo_export.c
-rw-r--r--   1 ...  1652  4 22 08:35 _cgo_export.h
-rw-r--r--   1 ...    13  4 22 08:35 _cgo_flags
-rw-r--r--   1 ...  1013  4 22 08:35 _cgo_gotypes.go
-rw-r--r--   1 ...   653  4 22 08:35 _cgo_main.c
-rw-r--r--   1 ...   324  4 22 08:35 main.cgo1.go
-rw-r--r--   1 ...  2028  4 22 08:35 main.cgo2.c
```

#### 2.2 函式呼叫入口 \_cgo_export.c

在 C 語言程式碼中呼叫 add 函式時，最先進入的是位於 \_cgo_export.c 中的呼叫入口。該入口函式定義如下：

```
int add(int a, int b)
{
    __SIZE_TYPE__ _cgo_ctxt = _cgo_wait_runtime_init_done();
    typedef struct {
        int p0;
        int p1;
        int r0;
    } __attribute__((__packed__)) _cgo_argtype;
    static _cgo_argtype _cgo_zero;
    _cgo_argtype _cgo_a = _cgo_zero;
    _cgo_a.p0 = a;
    _cgo_a.p1 = b;
    ...
    crosscall2(_cgoexp_ec46b88da812_add, &_cgo_a, 12, _cgo_ctxt);
    ...
    return _cgo_a.r0;
}
```

在這個函式原始碼中主要包含兩塊功能：

第一是對 Go 語言執行時的初始化，這是由 \_cgo_wait_runtime_init_done 函式完成的。因為 Go 函式還是需要由 Go 執行時來執行，所以確保 Go 執行時已經初始化是必要的。

第二是呼叫 runtime 的 crosscall2 函式，把呼叫轉交給 Go runtime 來處理。

在呼叫runtime 的 crosscall2 之前，先定義了一個包含所有輸入引數、輸出引數的 \_cgo_argtype，並將 C 語言輸入的兩個引數打包進來。這樣訪問 \_cgo_a 就可以獲取到所有的輸入和輸出引數。

另外也告訴 runtime 該函式的在 Go 語言實現的入口函式名是 \_cgoexp_ec46b88da812_add。等 runtime 中的邏輯執行完了後要回撥這個函式來進一步執行指。

#### 2.3 Go runtime cgo 執行

在上一小節我們看到了 Go runtime 的入口是 crosscall2 函式。這是一個純彙編寫的函式，其原始碼位於 runtime/cgo/asm_amd64.s 檔案中。

```
//file:runtime/cgo/asm_amd64.s
TEXT crosscall2(SB),NOSPLIT,$0-0
    PUSH_REGS_HOST_TO_ABI0()

    // Make room for arguments to cgocallback.
    ADJSP    $0x18
    MOVQ    CX, 0x0(SP)    /* fn */
    MOVQ    DX, 0x8(SP)    /* arg */
    // Skip n in R8.
    MOVQ    R9, 0x10(SP)    /* ctxt */

    CALL    runtime·cgocallback(SB)

    ADJSP    $-0x18
    POP_REGS_HOST_TO_ABI0()
    RET
```

在計算機體系結構和程式設計中，ABI 定義了函式呼叫的約定，包括暫存器使用、引數傳遞等。不同的語言採用的 ABI 呼叫習慣是不一樣的。

這裡因為要從 C 語言進入到 Go 語言中執行，所以在 crosscall2 的開頭和結尾處有 PUSH_REGS_HOST_TO_ABI0、POP_REGS_HOST_TO_ABI0 兩個函式。PUSH_REGS_HOST_TO_ABI0 函式作用是儲存呼叫方使用的暫存器。等呼叫結束後再透過 POP_REGS_HOST_TO_ABI0 恢復這些暫存器的值。

接著透過 ADJSP 指令將棧擴張一些，把輸入引數入棧，然後呼叫 runtime·cgocallback 函式來進一步在 runtime 中執行。

```
//file:runtime/asm_amd64.s
TEXT ·cgocallback(SB),NOSPLIT,$24-24
    ......
havem:
    // 儲存執行緒棧
    MOVQ    m_g0(BX), SI
    ...

    // 切換到協程棧
    MOVQ    m_curg(BX), SI
    ...

    // 呼叫 runtime.cgocallbackg
    MOVQ    $runtime·cgocallbackg(SB), AX
    ...
```

cgocallback 函式很長，我對它進行了提煉和精簡。這裡面主要是進行了棧的切換。因為 C 語言是使用執行緒來執行的，而 Go 是使用協程來執行。所以這裡就需要儲存執行緒棧，並切換到協程棧，然後才能夠進入到 Go 函式中繼續執行。 執行完棧切換後，交由 runtime·cgocallbackg 中進一步處理。

```
//file:runtime/cgocall.go
func cgocallbackg(fn, frame unsafe.Pointer, ctxt uintptr) {
    gp := getg()

    lockOSThread()

    ...
    cgocallbackg1(fn, frame, ctxt)
    ...
}
```

在 cgocallbackg 函式中，已經是由協程來執行處理了。但這時候還要呼叫 lockOSThread 來告訴 Go 的排程器，要把當前的協程繫結在當前執行緒上執行，不要把它交給其它執行緒。

接著呼叫 cgocallbackg1，在這個函式中呼叫 reflectcall，正式進入到使用者定義的 Go 函式。

```
func cgocallbackg1(fn, frame unsafe.Pointer, ctxt uintptr) {
    gp := getg()
    ...

    var cb func(frame unsafe.Pointer)
    cbFV := funcval{uintptr(fn)}
    *(*unsafe.Pointer)(unsafe.Pointer(&cb)) = noescape(unsafe.Pointer(&cbFV))
    cb(frame)
    ...
}
```

#### 2.4 Go 語言函式

從runtime出來後首先進入到的函式並不是我們寫的 Go 函式程式碼，而是由 cgo 生成的一個樁程式碼。在樁程式碼中，是為了將引數轉換成 Go 正常的引數列表。

這個樁程式碼位於 \_cgo_gotypes.go 檔案中。

```
//go:cgo_export_dynamic add
//go:linkname _cgoexp_ec46b88da812_add _cgoexp_ec46b88da812_add
//go:cgo_export_static _cgoexp_ec46b88da812_add
func _cgoexp_ec46b88da812_add(a *struct {
        p0 _Ctype_int
        p1 _Ctype_int
        r0 _Ctype_int
    }) {
    a.r0 = add(a.p0, a.p1)
}
```

透過代理函式呼叫到 main.go 函式中定義的 add 函式。

```
//export add
func add(a, b C.int) C.int {
    return a + b
}
```

經過漫長的路徑，一個 C 函式呼叫 Go 函式的執行流總算是打通了。

### 三、總結

我們來總結一下 C 語言呼叫 Go 語言函式的底層執行過程。

總體上來看，跨語言的呼叫是由三部分程式碼來配合執行的。分別是使用者程式碼、cgo生成的樁程式碼、Go語言執行時。

- 在 C 語言程式碼中呼叫 add 函式時，最先進入的是位於 \_cgo_export.c 中的樁程式碼。

- 接著進入 Go 語言執行時，包括 crosscall2、·cgocallback、cgocallbackg、cgocallbackg1 等函式。在這些執行時函式中儲存了呼叫方的暫存器、將執行緒棧切換到了協程棧、把協程鎖定到當前執行緒上執行。

- Go 語言執行時執行完後，透過 \_cgo_gotypes.go 中的樁程式碼 \_cgoexp_ec46b88da812_add 函式後真正進入到 Go 函式中執行。

我們在很早的一篇[函式呼叫太多了會有效能問題嗎？](https://mp.weixin.qq.com/s/G30VtOIYjx2Wa54xlO7udw)文章中曾經分析過 C 語言內部的函式開銷。每個 C 語言函式大概只需要 8 個指令，平均耗時 0.43 納秒。

透過今天的文章我們可以看到跨語言的函式呼叫的執行過程是非常複雜的，要比語言內部的函式呼叫要複雜的多。所以在效能上開銷也是要大於普通函式呼叫。但由於仍然是屬於程序內部的呼叫，不像 RPC 一樣需要進行核心協議棧處理、協議序列化/反序列化。所以還是比 RPC 呼叫效能要好的。也就是說在效能開銷上，語言內函式呼叫 < 跨語言函式呼叫 < RPC呼叫。
