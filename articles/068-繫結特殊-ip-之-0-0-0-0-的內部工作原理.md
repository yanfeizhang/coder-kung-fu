# 繫結特殊 IP 之 0.0.0.0 的內部工作原理

一、bind 過程

我們來看一下 bind 的相關內部過程，它的核心是 inet_bind， 其原始碼位於 net/ipv4/af_inet.c 中。我們只看和今天問題相關的部分。

這個函式有兩個重點引數，分別是 sock 和 uaddr。 其中 sock 是我們剛建立出來的 socket 物件，uaddr 的值就是我們在自己的程式碼裡傳入的 addr 值。函式接下來的 inet 是獲取了 socket 核心物件中的一部分。

在 inet_bind 的函式體中， 將要繫結的 IP 地址 addr->sin_addr.s_addr（ 0 ） 設定到了 socket 的 inet->inet_rcv_saddr 成員中 ，將要繫結的埠設定到了 inet->inet_sport 成員上。

接下來伺服器在 listen 的時候會把當前 socket 新增到一個 listen 狀態的 hash 表中，瞭解就行了。接下來咱們看當使用者握手包到達的時候的處理過程。

二、響應握手請求

在收到來自客戶端資料包的時候（包括握手請求），會進入到 tcp_v4_rcv 這個核心函式中。在這裡會讀取資料包的 tcp 頭和 ip 頭。其中在 tcp 頭中有 ip 和埠的四元組。

在 \_\_inet_lookup_skb 這個函式內部會尋找伺服器上處理該資料包的 socket。先檢視是否有已經建立的連線，如果沒有就尋找合適的 listen 狀態的 socket，以進行握手。我們直接檢視查詢 listen socket 的 \_\_inet_lookup_listener。

在 \_\_inet_lookup_listener 中遍歷同 hash 值的所有在監聽的 socket。挨個計算匹配分數，並把匹配分最高的挑選出來，就是要握手的 socket 物件了。

我們重點來看下 compute_score，我們今天問題的答案就藏在它裡面。在看原始碼之前先回憶一下，上面我們在 bind 地址為 INADDR_ANY 的時候，核心會把 listen socket 的 inet_rcv_saddr 設定為 0。來看原始碼:

在計算匹配分的時候會判斷 listen 狀態的 socket 中 bind 時記錄的 inet_rcv_saddr。如果它不為 0（bind 時指定了 IP），則資料包中的目的地址必須和它匹配才行。而 如果為 0（bind 時設定 IP 是 INADDR_ANY， 亦即 0.0.0.0），則不會進行 IP 地址的比對就能計算出正的匹配分 。

四、結論

可以用一句話來總結 0.0.0.0。如果一個服務是繫結到 0.0.0.0 ，那麼外部機器訪問該機器上所有 IP 都可以訪問該服務。如果服務繫結到的是特定的 ip，則只有訪問該 ip 才能訪問到服務。

實現的原理也很簡單，如果 bind 時繫結的是 0.0.0.0(INADDR_ANY)，則核心在查詢 listen 狀態的 socket 的時候不進行目的地址匹配。反之，則必須要網路包中的目的地址和該 socket 上的 IP 匹配才能訪問！
