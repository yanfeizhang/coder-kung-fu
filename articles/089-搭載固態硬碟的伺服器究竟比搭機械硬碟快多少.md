相信大家都知道固態硬碟的優勢在於速度比傳統的機械硬碟要快，所以現線上上伺服器裡越來越多看到固態硬碟的出現。不過作為一個對效能數字斤斤計較的開發，我想更精確地弄明白搭載 SSD 的伺服器在 IO 效能上比搭載 HDD 的究竟快多少，順序 IO 情況下快多少，隨機 IO 情況下又能快多少？終於在最近抽空進行了一次效能測試比較。

1 測試環境

分別找了兩臺伺服器，其磁碟 (Disk) 都是 Raid 陣列，分別是搭載 SSD 和 HDD，更詳細的設定如下：

- HDD 實機：Raid 卡型號是 PERC H730 Mini，1GB RAM 快取 (Cache)；4 塊 500GB SSD 組成的 raid5，可用容量 1.3T
- SSD 實機：Raid 卡型號同上，7 塊 300G HDD 硬碟組成的 Raid5，可用容量 1.6T

好了，比賽選手已經就位，再選擇壓測工具 fio。指定比 (壓) 賽 (測) 規 (參) 則 (數) 如下：

- IO 引擎：為了給硬碟充分施壓，選用非同步方式 libaio
- PageCache：為了更接近磁碟本身效能，開啟 Direct 參數繞開 Linux 系統的記憶體 (Memory) 快取
- 壓測物件：穩妥起見，沒有使用裸裝置，用的檔案
- 檔案大小：100GB，因為我的 Raid 卡快取是 1G，保證遠遠大於快取
- 排程策略：選擇常見的 noop

對比測試正式開始。

這個資料看來，在順序 IO 情況下，其實搭載 HDD 的伺服器 IO 效能並沒有被搭載 ssd 的落下太多。這是因為

- 順序 IO 的情況下，RAID 卡的命中率高，尤其是設定了 RAID 預取
- 本身順序 IO 也是機械磁碟工作最擅長的狀態

所以，現代在伺服器領域裡，SSD 只是應用越來越多了，但並沒有能夠全面替代 HDD。原因之一是因為機械硬碟的順序 IO 其實並不慢，再加上 Raid 的加持，所以還有很大的市場佔比。比較完了順序 IO，我們再來比較另外一個應用場景，隨機 IO。

3 隨機讀取 PK

還記得開頭的 fio 壓測參數中我們把 Page Cache 給禁用了，再加上測試檔案的大小定的是 100GB，這個大大超過了 Raid 卡的快取大小。所以根據這個前提下的隨機 IO，各級快取基本都失去用武之地了，IO 表現速度就完全看硬碟自身了。

再看固態硬碟下的 4K IO Size 下的表現。

- 頻寬角度看，仍然有 32M，比 HDD 能快幾十倍
- 延遲角度看，大約 120us 左右。比 HDD，就是 4400：120，也是幾十倍的提升

4 結論

在伺服器級別的機器上，因為有 Raid 卡快取的加持，順序 IO 的情況下，根據 HDD 組成的 Raid 陣列伺服器在 IO 效能上並沒有太落下風。

但是在隨機讀取的場景下，無論頻寬還是延遲指標，SSD 都要比 HDD 快幾十倍以上。所以在伺服器中應用 SSD，更主要解決的是隨機 IO 的問題。所以如果你的伺服器裡存在過多的 Page Cache，Raid 卡快取都兜不住的隨機 IO 請求，那麼請把 HDD 更換成 SSD 吧。
